# 星岛学园全站页面 UI 审查与优化设计

**状态：** 自审通过并进入实施；全站 UI 已逐组优化，加载过渡补充轻量动效；完整人工验收仍在进行。

## 1. 目标

逐页检查并优化星岛学园所有用户可见页面，让学生和陪伴者能看懂当前状态、找到下一步操作，并在桌面、平板和手机上舒适使用。页面没有数据时提供明确的空状态，不留空白区域；数据加载失败时显示错误与恢复操作，不将错误伪装成“暂无数据”。

优化应延续已经确认的品牌页眉、右侧浮层菜单、首页四个区域、成长中心分域展示和设置内的数据管理入口。重点是把现有各页的视觉层级、信息密度、空状态、响应式布局和交互反馈统一到项目现有设计系统中。

## 2. 方案与选择

### 方案 A：一次性统一重排所有页面

集中调整全局样式和页面布局，交付速度快；但不同页面的数据来源和交互状态容易被同一套结构压平，回归影响也集中。

### 方案 B：逐页族审查并迭代（采用）

先统一页面基础层级与空状态规则，再按首页/课程、学习、成长、闯关、设置与数据管理、系统状态逐组审查。每组都检查桌面与窄屏、浅色与深色、键盘交互，再推进下一组。该方案符合用户已选的“逐页优化”，可逐页确认实际内容与现有行为。

### 方案 C：只补齐空状态

能快速解决留白，但不能回应用户提出的整体适配性、可视性和交互性优化要求，因此范围不足。

## 3. 已确认的方向与设计边界

- 保留现有导航和信息架构：页眉左侧品牌，右侧菜单；菜单浮在页面上；设置及备份恢复按现有独立入口组织。
- 保留首页“继续学习、当前进度、最近学习记录、闯关入口”的顺序。
- 课程学习和闯关进度分别显示、分别使用现有数据来源；不得合成分数或互相修改。
- 保留学习任务、答题器、闯关提交、备份恢复、学习起点和现有路由行为；本项目以 本地优先 和静态部署为前提。
- 继续使用 React/Vite、已安装的 `animal-island-ui` 和 `naive-icons`，不增加首版不需要的依赖或后端。
- 本轮浏览器草图仅用于确认方向；其临时 CSS 不作为产品实现模板。正式实现须遵循已安装组件的类型定义、仓库主题变量及 Animal Island 设计规范。

## 4. 页面覆盖清单

以下范围按 `src/app/router.ts` 和 `src/App.tsx` 当前可见页面族梳理。实现计划开始前须再核对路由和工作区状态；任何新增或删除的用户可见路由都应加入清单。

| 页面族 | 当前路由或入口 | 本次审查重点 | 需要明确呈现的无数据/空状态 |
|---|---|---|---|
| 全局页眉、导航、页脚与提示 | 所有页面；全局菜单、教材迁移提示 | 品牌与菜单层级、菜单遮罩与关闭、移动端触达、页脚占位、提示不遮挡主要操作 | 不适用；加载与提示不得造成主内容留白或被遮挡 |
| 首页 | `/` | 四区顺序、主要操作优先级、信息密度、窄屏顺序 | 没有可继续场次、学习/闯关计数为零、没有近期记录、摘要读取中或失败 |
| 课程目录 | `/courses` | 年级/学期/学科切换、课程卡片层级、开放状态、选择结果与返回路径 | 当前年级/学期/学科组合没有可展示的已登记课程时给出说明；与“正在准备”及加载错误区分 |
| 单元概览与任务选择 | 课程单元路径及任务路径 | 教材位置、难度/任务导航、完成状态、返回目录入口、深链标题与焦点 | 计划开放内容或所选难度暂无可开始场次时说明原因和返回路径；若有效单元缺少任务结构，按内容完整性问题处理，不当作普通空列表 |
| 学习答题与结果 | 学习场次路径 | 题目可读性、答题控件、进度、反馈、朗读、提交与退出，在不改题目行为的前提下优化布局 | 课程/场次加载中、读取失败或路由失效使用独立状态；不得显示伪造题目或空白答题页 |
| 成长中心 | `/growth`、兼容路径 `/achievements`、`/challenges/growth` | 概览、学习星图、闯关成长的标签与内容层级；域之间清楚区分 | 零学习进度、尚无挑战记录、无近期活动、所选成长视图尚无对应记录；数据读取错误与空记录区分 |
| 闯关中心、路线与答题结果 | `/challenges`、`/challenges/group/:id`、`/challenges/task/:id` | 路线发现、任务状态、答题反馈、保存错误提示和完成结果 | 没有已登记路线、路线暂不可用、成绩/徽章为零；质量门禁状态不能伪装成空题库。合法路线缺少任务属于内容完整性问题，不显示为正常空列表 |
| 错题本 | `/challenges/wrong-questions` | 分类切换、题目列表、空分类状态、返回挑战入口 | 从未答错与当前分类没有错题使用可理解的说明；记录读取失败不显示为空 |
| 设置与数据管理 | `/settings`、`/settings/backup` | 主题、语音、学习起点、偏好说明；备份导入/导出、预览、冲突、安全合并、恢复点、隔离记录和故障帮助 | 没有注册学习单元、尚未选择备份文件、没有本机恢复点或隔离记录为空时分别说明；储存失败、导入失败和真正空数据分开呈现。备份文件由用户选择，不虚构历史备份列表 |
| 应用级状态页 | 路由加载、课程加载失败、未开放、未找到 | 标题、说明、恢复入口、焦点移动与视觉一致性 | 加载、暂不可用、教材准备中、无效路径各自有明确状态和合适下一步；不能使用单一“无数据”卡覆盖所有情况 |

模态框、确认对话框、抽屉、保存提示、音频不可用提示等也纳入其所属页面的交互审查；不因其是浮层而遗漏键盘和窄屏检查。

## 5. 空状态设计

空状态应帮助用户理解“现在是什么情况”和“下一步可以做什么”，而不是只显示数字 0 或一行弱化说明。

- 每个数据列表或摘要在空数据时使用完整但克制的视觉容器，至少包含简短标题和解释；有合理下一步时提供一个明确主操作。
- 图标只使用 `naive-icons`；不使用 emoji、Unicode 符号或手绘 SVG。空状态文案面向 7–12 岁学生，鼓励但不制造压力。
- 以下状态必须区分：尚未产生数据、筛选无结果、尚未开放/正在准备、加载中、本机数据读取失败、存储写入失败。
- 错误状态应沿用各领域已有的保护说明和恢复操作。特别是闯关数据错误不得自动删除或覆盖记录；数据管理页不得把无法读取显示成“没有备份”。
- 不编造历史活动、题目、课程数量、徽章或成绩；零值只在真实数据源确认后呈现。
- 相邻模块有各自的恢复操作时，不重复放置多个同权重按钮；不同空状态共享视觉语法，但标题、说明和操作按当前页面语境定制。

## 6. 视觉与交互规范

- 复用 `animal-island-ui` 的 Button、Card、Tabs、反馈和表单控件；自定义布局使用仓库中已定义的 `--animal-*` / `--island-*` 主题变量，不在页面新增另一套颜色体系。
- 保持暖色纸面、自然绿主色、圆角和清楚的标题层级；主要按钮、卡片阴影、焦点、图标、动效遵循已安装 UI 包及项目规则，不手工覆盖组件的颜色/圆角/阴影。
- 页面先呈现标题和关键操作，再呈现主要内容；控制长段文案和重复边框。多列布局只用于宽屏，窄屏改为自然单列，内容顺序与阅读顺序一致，不横向溢出。
- 加载过渡使用轻柔、低幅度的星环和指南针动效，并用简短状态文字说明进度；动效不延迟页面内容出现，系统开启 `prefers-reduced-motion` 时停用。
- 所有页面兼容浅色、深色和系统主题。状态不能仅靠颜色区分；文字对比、禁用态和选中态需清晰。
- 交互支持键盘和触控，使用语义化标题、按钮、链接、列表、标签与对话框；焦点可见，抽屉/对话框打开和关闭后的焦点行为正确。
- 尊重 `prefers-reduced-motion`；播放音效失败不得影响任务交互；声音开关、数据存储保护和现有确认机制保持不变。
- 页面可在 390px 手机宽度、768px 平板宽度和 1365px 桌面宽度下检查；具体 CSS 断点交由实现者沿用项目现有规则并按内容验证。

## 7. 非目标

- 不改教材、课程注册范围、任务/题目、答案、评分、课程进度算法或闯关成长规则。
- 不新增账号、云端同步、遥测、网络语音、服务端存储或不必要依赖。
- 不改变已确认的全局导航、首页区域顺序、备份入口位置及课程/闯关数据边界。
- 不将空数据、加载失败和暂不可用状态混为一谈；不为了统一视觉而隐藏必要的存储风险提示。
- 本轮浏览器草图仍是临时材料；正式实现以本规格及其实施计划为范围，不把草图 CSS 直接复制到产品。

## 8. 验收标准

1. 上表每个用户可见页面族和全局浮层均完成实际 UI 审查；没有遗漏的可访问路由或页面状态。
2. 页面中原有的每个数据区域都有数据存在、空数据、加载和读取错误（适用时）的明确表现；“无数据”页面不留白，错误不会被显示成空数据。
3. 每个空状态文案准确、简短、鼓励；有用的页面提供明确下一步，操作指向有效路径。
4. 原有学习和挑战交互、教材内容、进度与存储语义不变；备份安全合并、预览、恢复点、隔离记录和数据保护文案保持有效。
5. 全站在浅色、深色、390px/768px/1365px 视口、键盘焦点和减少动态效果下通过逐页人工检查；无文字截断、横向溢出、按钮被遮挡或状态仅靠颜色表达。
6. 组件继续使用已安装 UI 包和 `naive-icons`，无新依赖、手绘图标或页面级私有设计 token。
7. 实施后运行项目要求的生产构建与 `git diff --check`；根据受影响页面运行相应单元/端到端验证。未能运行的验证必须列明原因和剩余风险。

## 9. 实施者可决定的细节

按实施计划推进时，实施者可根据各页真实内容决定具体间距、网格比例、同一空状态模式中的组件组合，以及是否抽取共享空状态组件。每项选择须遵守第 3–7 节，不得改变数据含义、路由、课程流程或已确认的信息架构。
