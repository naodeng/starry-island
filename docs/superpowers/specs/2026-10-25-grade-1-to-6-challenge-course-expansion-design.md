# 一至六年级闯关课程扩展设计

状态：已获用户批准（2026-10-25）；2026-10-26 复审修订。本文确定逐年级扩展范围和放行方式；复审修订不改变已批准的产品目标。

## 1. 目标与边界

从一年级开始，按年级顺序完成一至六年级上下学期的语文、数学和英语挑战内容；一个年级达到本文的完成门槛后，再进入下一个年级。每个正式编号单元建立单元挑战；每个年级、学期和学科建立前半学期、后半学期、期末综合三个阶段挑战。

本设计遵守已确认的 PRD 与 REQ-001～REQ-085 基线：

- 只按课程注册表和已登记教材清单映射课程，不臆造教材单元或授课进度。
- 单元挑战只对应正式编号单元。主题、复习和综合实践条目可以进入学期阶段挑战；不得为它们虚构正式单元号或单元成就。
- 一年级语文按已登记教材目录是主题单元，没有正式编号单元，因此以学期阶段挑战覆盖，不额外创建语文单元挑战。
- 英语在课程元数据中标注的学校开设状态继续保持“未确认”；提供项目内挑战内容不代表已确认学校采用该课程。
- 题目、材料、提示、讲解、情境和反馈均为原创。课程题可以作为挑战候选，但须重新核对挑战任务目标、范围、难度和实际呈现。
- 不修改现有学习 Task、课程顺序、学习进度、答题方式或课程题目；不引入后端、账号或在线题目服务。

## 3. 扩展顺序

### 年级顺序

严格按一年级、二年级、三年级、四年级、五年级、六年级推进。未达到当前年级的完整门槛时，不将后续年级称为已开始或已完成。教材证据阻塞时，记录待核实事项，不以推测填充；该阻塞须解决后才能放行当前年级。

### 年级内顺序

每个年级按上学期、下学期推进；每学期按语文、数学、英语的课程目录顺序审计来源和正式单元。单元挑战按教材目录顺序逐组完成。某学科该学期的单元映射完成后，再建立该学科的前半学期、后半学期、期末综合三个阶段组；阶段映射的分半依据为该册全部正式章节，若没有正式编号章节则以登记主题作为依据。复习和综合实践可在范围及任务目标支持时作为额外来源，但不改变章节边界；不得纳入未登记的未来课程。

前半、后半阶段按教材目录顺序尽可能等分。存在正式编号章节时，以这些章节作为分半依据；奇数章节时前半取较少的一半，后半取余下部分，不让复习或综合实践条目改变章节边界。没有正式编号章节的课程（如一年级语文），以教材清单登记的主题条目顺序作为分半依据。该规则延续已确认的二年级上册数学 01～04 / 05～09 划分，只定义项目内阶段边界，不表示学校实际授课日历。复习和综合实践可以在教材范围与任务目标支持时作为阶段组补充来源，但须在映射证据中单独列明。测试验证分半依据互不重叠、合并覆盖全部章节或主题依据；期末综合不得引用该册未登记的未来内容。

## 4. 题库与题目审校标准

### 单元挑战

- 每组固定 5 个任务：2 个基础、2 个进阶、1 个高阶；基础和进阶的两个任务共同覆盖组核心知识点，高阶任务综合运用多个已学知识点。
- 每任务目标 15 题。每个难度档候选池至少 30 道有效、已审核、互不重复且兼容的题目，覆盖该档两个任务的知识点；最终组卷仍由现有确定性组卷器执行。
- 每单元候选池的核心题目来自该单元范围。原创补题只填真实缺口，不以换数字、人物、物品或同义措辞制造题量。

### 学期阶段挑战

- 每个年级 × 学期 × 学科固定三个阶段组，共 18 组/年级；每组同样包含 5 个任务：2 个基础、2 个进阶、1 个高阶。
- 每任务默认 25 题、最多 30 题。候选池按 PRD 至少达到该档最大目标题量的两倍；默认 25 题时至少 50 道有效候选。
- 每阶段的来源单元、课程主题、核心知识点和阶段边界逐项有教材目录/课程注册证据。期末综合只使用该学期已登记且已教范围内的内容。

### 逐题审校

逐题审校适用于每个候选池的全部题目，不只覆盖固定种子实际抽中的题目。质量基线沿用[课程目录与内容编写规范](../../curriculum/authoring-standard.md)及[课程内容分层审核规则](../../curriculum/course-content-review-rules.md)的“学期 → 单元 → 任务 → 题目”核验：确认教材版本与册次范围、单元主题、任务目标与难度，再逐题检查题意、答案、提示、解释、年龄适配、重复和学科正确性。挑战题还须按[闯关系统开发协作指南](../../challenges/DEVELOPMENT_GUIDE.md)核对候选池去重、知识点映射、组卷兼容性、题目 ID、答案键与学生实际看到的交互。

作者逐题检查最终呈现、答案、提示、讲解、年级适配、课程范围、知识点映射、难度、选项唯一性、题型键映射、ID 稳定性和同任务/跨难度重复。数学独立复算；英语核对拼写、词义、语法及交流目的；语文核对题意、事实依据、文本证据和年级术语。分类、配对、排序和模板题按学生实际看到的完整内容及运行时映射复核。

每组使用闯关开发指南规定的中文逐题台账，至少记录稳定题目 ID、难度、知识点、答案、复核说明与作者自审状态。课程题审校记录只证明课程题本身的范围和内容检查，不能替代该挑战组对候选池、任务难度和组卷呈现的复核；已有挑战台账也仅在题目 ID、内容和当前候选范围逐项对应时复用。作者自审符合 REQ-078；不得声称已完成独立教育工作者审核。尚未审完或有未解决正确性/教材范围问题的组保持计划中或不可用，不得发布。

## 5. 每个年级的完成门槛

进入下一年级前，当前年级必须同时满足：

1. 上下学期课程来源、版本、教材目录、学科开设状态和单元分类均已按仓库来源规则核实；若学校开设状态仍无可靠证据，明确保留“未确认”，不得据此声称学校采用该课程，也不把项目提供挑战内容当作开课证明；不得拼接不同教材版次。
2. 覆盖工具所列该年级全部正式编号单元组和 18 个学期阶段组；每组五个任务的身份、映射和状态正确。
3. 已发布组的所有候选题逐题审校完成；有效候选池、题目差异、知识覆盖和确定性组卷模拟通过 `npm run challenge:quality`。
4. `npm run challenge:coverage` 能准确反映当前年级已发布情况；剩余年级仍如实显示缺口。源素材盘点只作为候选盘点证据，不代替内容审校。
5. 课程行为和学习进度回归检查、适用的题目测试、`npm run build` 与 `git diff --check` 通过；没有引入 500 kB JavaScript 分块警告。
6. 中文挑战题审校台账、[内容变更记录](../../challenges/CONTENT_CHANGELOG.md)、路线图及需求追踪证据已更新；作者自审、自动检查、人工内容核对分别陈述，不互相替代。

质量命令的结构通过不等于教学内容正确；未完成必要人工题目核对时，不能通过发布状态或“题库完整”措辞绕过。

## 6. 工程实施约束

- 按仓库 TDD 约定，为新增内容映射、题型行为和组卷约束先建立失败测试，再实现对应内容；不为凑覆盖率改变生产题目语义。
- 沿用现有挑战清单、领域验证器、题型渲染器、确定性组卷和质量工具；不新增平行题库格式或第二份权威清单。
- 题库清单继续按年级、学期、学科拆分 JSON 片段；每个正式组 ID 只在一个片段中定义并且只合并一次。既有核心清单和一年级数学单元 5～9 片段保留原组与稳定 ID，新片段只追加尚未登记的组，不得重复抄入旧组。
- 沿用 `vite.config.ts` 的 Rolldown 分块配置，但需按年级、学期、学科拆分题库清单和补题模块；若任一分块接近或超过 500 kB，再按单元/阶段边界细分。全量构建不得产生超过 500 kB 的 JavaScript 分块警告；不得把静态合并误称为运行时按需加载。
- 每一批修改只包含当前年级需要的挑战内容、相关测试和文档，不改现有学习课程 Task 或课程进度存储。
- 内容修改按闯关开发指南分级并记录风险、影响任务和实际检查结果。指纹变化保留审核状态；严重问题才按已确认流程显式停用。

## 7. 本阶段交付物

通过本设计后，先为一年级编写独立实施计划，再按一年级范围落地：缺失组的教材/课程映射、原创补充题、挑战清单、逐题中文台账、针对性测试与文档更新。每年级完成后更新覆盖报告和路线图，再开始下一年级。各阶段的提交或推送遵从用户当时指示；本设计不预授权提交、推送、合并或部署。

本设计本身不代表任何新增挑战组、题库或年级已经实现或通过审核。
