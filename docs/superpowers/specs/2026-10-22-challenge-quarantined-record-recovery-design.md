# 闯关隔离记录安全恢复设计

状态：供用户评审的架构规格。本文定义隔离记录的单条预览与安全恢复边界，不表示实现已经完成，也不代表任何设备上的隔离记录已经可恢复。

## 1. 目标与边界

为闯关数据增加由用户主动发起的隔离记录检查与恢复能力。只有当前格式完整有效，或能够按仓库已有的明确迁移规则无损归一化的记录，才允许恢复；恢复前先预览，用户确认后才写入。

恢复只作用于闯关域独立的 IndexedDB。不得读取、修改或推断现有课程学习进度，不新增后端、上传、遥测或自动修复流程。成绩和答案必须来自隔离记录本身；不得推测缺失字段、重算未保存的作答历史或补造分数。

本功能按单条记录操作。未知格式、缺少关键数据、来源不受支持、主键不匹配或目标主键已占用的记录继续留在隔离仓库，原文仍可按现有方式导出。

## 2. 已确认产品决定

- 仅在用户主动检查某条记录后提供恢复预览；预览本身只读。
- 只有用户对该条记录明确确认后才执行写回。
- 活动记录写入和隔离记录删除必须在同一个 IndexedDB 读写事务内完成。
- 仅恢复已有完整记录或确定性迁移可识别的旧格式；不推断分数、答案、题目身份或缺失业务字段。
- 未知版本、关键字段缺失、来源键不一致和主键冲突一律保留隔离原文，不覆盖活动数据。
- 每次只处理一条记录；取消预览不改变任何数据。

## 3. 当前仓库事实

以下事实来自本次只读检查：

- 闯关数据存于独立 IndexedDB `starry-island-challenges`，当前数据库结构版本为 `4`。
- `quarantinedRecords` 使用自增主键；每条记录包含 `sourceStore`、`sourceKey`、`quarantinedAt`、`reasonCode` 和原始 `record`。
- 仓库在一次读写事务中先将异常数据复制到隔离仓库，再从活动仓库移除；事务失败时原数据保留。
- 当前仓库接口可读取隔离记录数量和内容，但 `getQuarantinedRecords()` 没有返回隔离仓库自增主键，因此无法安全定位某条重复或相似记录进行删除。
- 已有数据库迁移会为结构完整、缺少 `snapshotSchemaVersion` 的旧进行中快照补入版本 `1`；也会对符合已知恢复点格式的数据使用 `normalizeImportedChallengeBackupData()` 归一化其中的旧快照。未知或结构无效的数据不会猜测迁移。
- 当前记录完整性校验会检查进行中快照、进度、错题、最近题目 ID 和恢复点。缺少难度、未知快照版本等记录已由测试覆盖为隔离对象。
- 当前界面显示隔离数量并允许用户手动导出原始 JSON；普通备份和诊断报告不包含隔离原文。
- 仓库文档尚无真实用户设备隔离记录的库存或可恢复率数据。静态仓库审计不能读取这些本地浏览器数据。

## 4. 可恢复记录规则

恢复资格由一个纯函数根据隔离记录、隔离仓库主键和目标活动仓库快照计算。预览和最终提交必须调用同一套资格规则；事务提交前还需重读数据并复核。

### 4.1 共同条件

以下条件必须全部满足：

1. 隔离仓库主键可被稳定识别并返回给仓库层调用方。
2. `sourceStore`、`reasonCode` 属于下表中的已知组合，且 `sourceKey` 类型符合该活动仓库的主键类型。
3. 候选记录符合当前活动仓库的完整结构校验，或符合本规格明确允许的一种旧快照归一化规则。
4. 记录内的业务主键与 `sourceKey` 完全相等。
5. 目标活动仓库中不存在该主键。已有目标记录不论内容是否相同，均视为冲突；不比较后合并，也不覆盖。
6. 所有转换只改动表中列明的版本字段，其余数据按稳定结构比较保持不变。

不符合共同条件的记录不可恢复。界面给出固定中文原因，不显示原始异常文本；用户仍可导出隔离原文。

### 4.2 首版允许的来源与格式

| 来源仓库 / 原因代码 | 可恢复条件 | 允许转换 |
|---|---|---|
| `attempts` / `invalid-attempts` | 当前快照格式通过完整校验，且 `taskId` 等于 `sourceKey` | 无；原样恢复 |
| `attempts` / `invalid-attempts` | `snapshotSchemaVersion` 缺失；除该字段外符合仓库已有旧快照校验；`taskId` 等于 `sourceKey` | 仅补入当前已知快照结构版本 `1`，随后再次通过当前完整校验 |
| `taskProgress` / `invalid-taskProgress` | 当前进度格式通过完整校验，且 `taskId` 等于 `sourceKey` | 无；原样恢复 |
| `wrongQuestions` / `invalid-wrongQuestions` | 当前错题格式通过完整校验，且 `questionId` 等于 `sourceKey` | 无；原样恢复 |
| `challengeMeta` / `invalid-recent-question-ids` | 元数据键为 `recent-question-ids`，与 `sourceKey` 一致，且通过当前完整校验 | 无；原样恢复 |
| `challengeMeta` / `invalid-recovery-point` | 恢复点外层是已知格式版本 `1`；字段、时间关系和内含闯关数据均可验证；元数据键与 `sourceKey` 一致 | 仅对内含的旧进行中快照应用现有版本 `1` 归一化规则，随后再次完整校验 |

恢复点已过期或尚未生效时不恢复到活动仓库；隔离原文保留供用户导出。把恢复点写回只恢复该恢复点元数据，不会自动把其内含的成绩、答案或错题合并到活动记录。

当前允许的转换集合仅为上述旧快照版本补入。任何新的格式迁移必须先更新需求/规格、纯函数测试和此表；不得通过“尽量兼容”扩展为字段补默认值、答案推断、成绩重算或 ID 修正。

### 4.3 不可恢复示例

- 未知 `snapshotSchemaVersion`，包括大于当前支持版本的值。
- 缺少必需业务字段，例如难度、题目快照、答题时间或成绩总题数。
- `sourceKey` 与记录自身 `taskId`、`questionId` 或元数据键不一致。
- 已知来源以外的对象仓库或未知 `reasonCode`。
- 多条隔离记录指向同一目标主键，且其中一条已经恢复或活动仓库已有该主键。
- 无法完整验证的恢复点、其内含未知快照格式或不满足有效期规则的恢复点。

## 5. 用户流程

1. 闯关数据管理区保留现有隔离数量和隐私提示，并增加“检查可恢复记录”入口；应用启动时不自动运行恢复。
2. 用户打开列表后，界面按隔离记录逐条显示安全元数据：来源类别、记录键、隔离时间、原因和当前判断（可预览 / 暂不可恢复）。列表不渲染题目、选项、答案、讲解或原始 JSON。
3. 用户选择一条记录后，系统生成只读预览。预览明确展示目标记录类别、目标键、资格判定、将执行的唯一字段转换（如适用）及冲突状态。对“原样恢复”的记录标注“不修改记录内容”。
4. 只有资格通过且目标键当前空闲时，才显示该记录的最终确认操作。确认说明该次操作会把一条记录写回指定闯关数据仓库，并仅在成功提交后删除对应隔离副本。用户可以取消，取消不写入。
5. 确认后仓库重新读取隔离记录和目标键，在同一读写事务中复核记录身份、重新执行资格校验、以不覆盖语义写入活动记录，并删除该隔离主键。
6. 成功后刷新隔离数量和列表，给出已恢复记录类别的中文提示。任何失败都保留隔离原文并显示可重试的安全说明。

此流程是逐条恢复，不是批量恢复。用户需分别预览和确认每条记录。

## 6. 仓库接口与事务要求

### 6.1 隔离主键

仓库读取隔离记录时须同时读取 `getAll()` 与 `getAllKeys()`，按同一请求顺序配对，返回含 `quarantineId` 的记录包装类型。实现必须校验数量一致；不能配对时拒绝生成可操作预览。不得依赖记录数组下标作为身份。

`quarantineId` 只用于本地仓库的精确读取/删除，不写入普通备份、诊断报告或隔离导出文件。现有隔离导出目前直接序列化读取结果；实现时必须显式投影回原有隔离记录字段，确保新增主键不会意外改变导出格式。若出于排查需要扩展导出字段，另行评审。

### 6.2 预览接口

仓库新增只读预览能力，输入 `quarantineId`，返回：

- 隔离记录身份和安全摘要；
- 是否可恢复；
- 固定原因代码及中文可展示原因；
- 目标仓库和目标键；
- 是否会补入旧快照结构版本 `1`；
- 仅用于确认提交的候选记录快照或不可变令牌。

预览不得修改 IndexedDB。候选原始数据只留在当前应用内存中，不进入日志或 URL。用户界面只显示安全摘要与转换说明，不回显候选原始内容。

### 6.3 原子确认接口

确认接口接收精确的 `quarantineId` 及预览产生的候选快照/令牌。单个 IndexedDB `readwrite` 事务至少覆盖隔离仓库和对应目标活动仓库，并执行：

1. 重新读取隔离行；若不存在、主键身份不符或内容与预览不一致，中止并返回“预览已过期，请重新检查”。
2. 重新读取目标主键；若已占用，中止且保留隔离行，返回冲突。
3. 在事务上下文中重新验证来源、原因、格式、业务键、转换结果和完整当前结构。
4. 使用 `add()` 或等效的禁止覆盖操作写入活动仓库，不使用会静默替换已有内容的 `put()`。
5. 仅在活动记录写入请求成功后删除对应 `quarantineId`。
6. 事务提交成功后才向 UI 报成功。

事务中任何请求失败或事务中止时，活动记录与隔离原文必须保持事务前状态。对页面收到的不确定结果，应重新读取两仓库：若隔离行仍在，重新预览；若隔离行已消失且活动记录与原候选内容完全一致，显示已完成；若目标记录不一致，则显示冲突，不推断为成功，也不再次生成成绩。

`challengeMeta` 的恢复点只恢复为元数据记录，不触发已有恢复点的合并流程。成绩、答题和错题记录也不走备份安全合并算法：一条隔离记录只恢复到原始来源仓库，绝不与活动记录合并。

## 7. 隐私、无障碍与用户可见文案

- 操作仅在本机 IndexedDB 执行，无网络请求、上传、遥测或后台自动重试。
- 普通备份和脱敏诊断仍排除隔离原文；用户主动导出原始隔离记录的现有隐私提示保持不变。
- 列表与确认界面不展示答案、选项、讲解全文、原始对象或浏览器内部错误。原因采用固定中文映射。
- 列表、预览、确认、取消和状态提示均支持键盘焦点、语义化按钮与屏幕阅读器；状态不能只用颜色表达。
- 明确区分“可恢复”与“已恢复”，并说明失败/冲突时原始记录仍保留。
- 不修改学习 Task、课程进度、原有答题器或已保存学习交互。

## 8. 错误与边界状态

| 情况 | 行为 |
|---|---|
| 目标主键已存在 | 阻止恢复；不覆盖、不合并；保留隔离行，提示该记录与本机数据冲突 |
| 预览期间隔离行被删除或改变 | 拒绝过期预览；保留现有状态并要求重新检查 |
| 来源或原因未知 | 标记暂不可恢复；允许现有原始导出 |
| 缺字段、未知版本或校验失败 | 标记暂不可恢复；不填默认值、不重建内容 |
| 恢复点已过期或尚未生效 | 不写入活动元数据；保留隔离原文 |
| 浏览器存储暂不可用、事务失败或配额错误 | 不报告成功；事务回滚，原记录保持可导出 |
| 用户取消 | 清除预览状态，不读写数据库 |
| 多条记录目标键相同 | 每次事务内重新检查；先成功恢复的一条占用目标键，后续记录冲突并继续隔离 |

## 9. 验收标准

### 领域与存储

- 对表中每一种受支持来源，验证当前完整格式可原样生成候选；旧快照只增加 `snapshotSchemaVersion: 1`，其他字段稳定比较完全相同。
- 验证恢复点只允许既有迁移函数能完整归一化的 v1 数据；未知版本、过期点和不完整内层数据均不可恢复。
- 缺少关键字段、来源不明、原因未知、业务键不一致和目标主键占用均返回明确不可恢复结果，不修改任一仓库。
- 预览为只读；确认事务成功时写入一条活动记录并删除同一隔离行。
- 任何提交失败/中止时没有半边提交：不出现活动记录已写而隔离原文丢失，或隔离行已删但活动记录未写。
- 两个连接或标签页同时确认同一记录时最多一个成功；另一个重新检查后看到已完成或冲突，不重复记分。
- 隔离记录从不被加入普通备份或诊断报告；课程学习存储及进度保持不变。

### 用户界面

- 只有用户打开数据管理并选择记录后才生成预览；页面加载和列表读取不会触发恢复。
- 预览展示目标、转换字段和结果；不会显示原始答案内容。
- 用户取消后记录不变；用户确认后仅显示事务确认的结果。
- 冲突、未知格式和校验失败记录都有可理解原因，并保持原始导出能力。
- 窄屏、浅色/深色、键盘焦点、屏幕阅读器语义和减少动态效果符合项目无障碍约定。

## 10. 测试方案

- 领域单测：资格允许规则列表、旧快照单字段归一化、恢复点归一化、未知格式/缺字段/错键/过期点拒绝、候选字段稳定性。
- 仓库集成测试（`fake-indexeddb`）：精确 `quarantineId` 配对、只读预览、原样恢复、旧格式恢复、主键冲突、预览过期、事务失败回滚、重复确认与两个 Repository 实例竞争。
- UI 组件测试：列表状态、预览摘要、转换说明、最终确认、取消、不可恢复原因、隐私字段未渲染、错误提示和数量刷新。
- 浏览器端到端测试：在本地浏览器隔离数据样例中预览一条已知旧快照、确认恢复，并验证原答题快照内容/答案不变、隔离数减少一条；另覆盖冲突记录仍可导出且原文未变化。
- 回归：闯关正常答题/进度、备份导入导出、数据清除与恢复点、现有学习 Task/进度均不受影响。

实现阶段按项目 TDD 流程先写失败测试再实现。具体文件、测试命令和任务拆分由规格评审通过后的实现计划给出。

## 11. 非目标

- 启动时、读取时或后台自动修复。
- 批量恢复或自动合并冲突记录。
- 导入用户导出的隔离 JSON 到活动仓库。
- 对未知格式做通用迁移、猜测缺失值、改写题目/任务 ID。
- 根据当前题目内容重算历史分数或补建完整作答记录。
- 删除或定期清理隔离原文。
- 改动现有学习进度、课程 Task、静态部署模式或 Local First 架构。

## 12. 实施前仍需核验

- 通过实际仓库类型与测试确定 `getAll()`、`getAllKeys()` 的配对错误处理及 `quarantineId` 类型；不能在当前文档中把 IDB 实现细节误报为已编码接口。
- 以已有数据迁移函数和当前结构校验器的实际导出/可复用边界实现资格校验，避免产生第二套结构校验规则。
- 确认已有 `getRecoveryPoint()` 的到期边界与本规格中的不可恢复预览一致。
- 通过独立 UI/端到端测试确定列表中键值的安全呈现与大量隔离记录时的可用性；不在本规格中假设用户设备的记录数量。
- 旧快照可恢复的实际数量必须在每台设备上按需只读预览后才能得知；不得仅凭仓库迁移测试宣称存在真实可恢复记录。
