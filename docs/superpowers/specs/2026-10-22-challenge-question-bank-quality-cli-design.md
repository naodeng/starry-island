# 闯关题库质量命令行工具与发布门禁设计

状态：供用户评审的架构规格。本文只定义 REQ-036～REQ-047 的方案，不表示工具、发布门禁或全课程题库已经实现。实施前仍须按本文“待验证事实”核对仓库和课程数据。

## 1. 目标与边界

为闯关题库建立一套可在本地和 GitHub Actions 运行的确定性质量检查：校验 Git 中的声明式题库清单，复用应用中的题目校验和组卷逻辑，模拟候选任务的组卷结果，生成可用状态报告，并在已声明发布的任务不满足硬性条件时阻止合并/发布。

工具是静态、只读的本地命令，不引入服务端、数据库服务器、云端内容管理或 AI 审核。它不修改题目、审核状态、指纹、挑战状态或浏览器数据，不代替教师/作者进行语义审校，也不改变现有学习任务、学习进度和交互。

本设计同时明确 REQ-039 的边界：未完成答题保存不可变题目快照；快照结构版本与题库内容版本分开记录。命令行工具校验题库内容，快照兼容性由应用的数据迁移及自动化测试验证，不读取用户设备数据。

## 2. 基线与仓库事实

### 已确认的产品决定

- REQ-036～REQ-047 的范围以本仓库[需求追踪矩阵](../../../challenges/REQUIREMENTS_TRACEABILITY.md)为准；当前规格只处理题库质量工具与对应发布门禁。
- 题目使用稳定全局 ID、声明式清单、内容指纹和 `active` / `disabled` / `deprecated` 生命周期；发布状态分为 `ready`、`planned`、`unavailable`。
- 每个难度的有效、已审核、可用且不重复的题池不少于该难度最大目标题量的两倍；组卷必须满足知识点覆盖，并接受多种子模拟。
- REQ-080 覆盖 REQ-037 的自动撤销规则：内容指纹变化保留 `approved` 状态。指纹用于追踪变化，旧审核不得被描述成针对新内容的新审核；指纹变化本身不得自动撤销审核或暂停发布。
- 作者可以自审，审核元数据保持最小字段。自动化质量检查不能替代必要的人工教学内容审核。
- 现有学习流程、静态部署和 Local First 边界保持不变；不增加首版不需要的后端服务。

### 当前仓库事实（以本次只读检查为准）

- 闯关域校验位于 `src/challenges/content/validateManifest.ts`，组卷位于 `src/challenges/domain/assemble.ts`，指纹位于 `src/challenges/content/fingerprint.ts`；应用目前加载 `src/challenges/content/pilot-manifest.json`。
- 当前校验已有重复 ID、重复内容指纹、审核字段、题型兼容、候选池两倍数量、知识点覆盖及组状态检查；指纹差异作为 `contentChanges` 返回，没有自动撤销 `approved`。
- 当前题目记录包含稳定 `questionId`、源 `activityId`、难度、知识点、生命周期、审核与答案泄露检查字段，以及审核指纹和最少审核信息。挑战组通过显式 ID 引用题目。
- 当前答题快照字段包含 `contentManifestVersion` 和冻结的题目/答案/顺序数据；`ChallengeAttempt` 尚无单独的快照结构版本字段。IndexedDB 当前结构版本为 3。
- `package.json` 尚无题库质量命令；`.github/workflows/quality.yml` 已在 `Quality` 工作流运行单测、覆盖率、静态构建和 Playwright 端到端检查。
- 当前清单只有两个本地试点组。已登记课程题目的总数不能代替经过审核、映射、去重和题型兼容检查后的有效候选题量。

## 3. 方案选择

### 采用：共享领域规则的只读命令行工具

增加一个薄的命令行入口，由它加载仓库中的题库清单和课程活动，调用现有或抽取后的无界面 TypeScript 校验、指纹、去重和组卷函数。验证规则只保留一份，应用运行时与 CI 使用同一套状态推导和组卷约束。报告以稳定 JSON 为机器接口，并输出中文 Markdown 摘要供本地和 CI 阅读。

这个方案复用当前试点校验，允许随年级、学期、学科和单元逐步扩展清单，且不把 Node/GitHub 专属代码带入浏览器模块。

### 不采用的方案

- 在 CLI 中重新实现一套校验/组卷算法：会与应用运行时规则漂移，难以证明报告状态和实际可玩的状态一致。
- 把质量报告作为另一份手工维护的发布清单，或由报告覆盖源清单：会形成重复事实源和生成文件冲突。
- 引入在线审核服务或 AI 自动判题/批准：超出 Local First、静态首版和人工内容审核边界。

## 4. 模块职责与数据流

建议模块边界如下；具体文件命名和 CLI TypeScript 执行器留待实现计划依据现有工具链核对。

| 模块 | 职责 |
|---|---|
| 质量命令入口（仓库脚本层） | 解析参数、加载完整课程与挑战清单、调用无界面领域校验、整理退出码、写出报告；不修改源文件 |
| 挑战清单加载器（内容层） | 校验清单结构与版本，建立题目/活动/课程单元索引，拒绝缺失或冲突来源 |
| 题目质量校验（共享领域层） | 校验 ID、审核元数据、生命周期、引用、题型、知识点、答案泄露检查和题池边界；计算当前指纹 |
| 确定性重复检查（共享领域层） | 对完整活动内容生成规范化指纹，识别精确重复；生成有序、可复现的相似题候选对 |
| 组卷模拟（共享领域层） | 调用生产组卷器，以固定种子重复组卷，验证输出数量、去重、知识点覆盖和约束 |
| 发布状态解析（共享领域层） | 将 `releaseIntent` 和阻断问题映射到 `ready` / `planned` / `unavailable`，供应用和 CLI 共用 |
| 报告格式化（脚本层） | 生成版本化 JSON 和中文 Markdown；报告排序稳定，失败信息可以定位到组、任务、题目或字段 |

数据流：Git 中的挑战清单和课程源内容 → 只读加载与结构校验 → 计算题目资格/指纹/重复候选 → 检查每个组和任务的候选池 → 多种子调用真实组卷器 → 推导发布状态 → 输出报告与退出结果。工具不得读取 IndexedDB、`localStorage`、学生答案或个人信息，也不访问网络。

当前 `pilot-manifest.json` 是唯一已有挑战注册清单。实施时应继续保持单一事实源；若为扩展完整课程而将其改为通用清单名称，必须在一次可审查迁移中同步更新应用引用、测试和文档，不得长期维护两个权威清单。

## 5. 质量规则

### 5.1 清单与稳定 ID（REQ-037、038、047）

- 清单结构、题目、组、任务和来源单元必须可解析，版本字段非空，所有引用必须存在且范围匹配。
- `questionId` 在整个清单和完整课程题库范围内唯一、非空且稳定；ID 不从题干/答案指纹派生。已弃用 ID 不得分配给另一道题；为不依赖 Git 历史扫描来识别旧 ID，清单应保留弃用记录作为墓碑。`activityId` 也必须唯一映射到一条挑战题目记录；题目可被多个组/任务引用。
- 所有审核字段遵循已确认的最小字段和作者自审规则。只有显式标记已审核、答案泄露检查已完成且审核时间/人员记录有效的题目，才可能进入有效题池。
- 指纹按当前 `fingerprintActivity()` 的规范化 JSON + SHA-256 语义计算，排除活动 ID、保留题目内容和判题相关字段。字段语义变化须作为兼容性变更审查，不能悄悄改变既有指纹含义。

### 5.2 指纹变更与审核语义（REQ-037、080）

- 当前内容指纹与 `approvedContentFingerprint` 不一致时，报告题目 ID、旧/新指纹和引用组/任务；报告中注明“内容自记录审核指纹后发生变化”，不得称其为自动未审核。
- 指纹变化不清除 `approved`、不自动停用题目、不改变发布意图，也不单独令 CI 失败。题目只有在作者显式更新生命周期或状态时才改变资格；需要重新审核时，由维护者根据风险检查并显式更新审核记录/指纹。
- 未发生变化时，报告也不得推断题目正确、无歧义或已通过教学审校；指纹只证明字节规范化后的内容是否匹配。

### 5.3 生命周期和进行中快照（REQ-039～041）

- `active`：可以参与新组卷，前提是其余资格检查通过。
- `deprecated`：从新组卷和新发布有效题池排除；已保存的进行中快照继续使用冻结题目内容。
- `disabled`：从新组卷排除，并作为明确的安全停用信号；当应用已载入包含该停用状态的当前清单时，若进行中快照包含该题，恢复/继续答题必须暂停并显示安全说明，不自动丢弃作答或进度。修复后由作者显式恢复 `active`，后续常规发布再解除阻断。
- 普通编辑、指纹差异和 `deprecated` 不阻断进行中快照；只有显式 `disabled` 才触发 REQ-041 的安全暂停。此语义落实严重缺陷必须显式禁用的流程，避免把每次编辑都变成暂停发布。
- 静态发布的生效边界：已打开且仍使用旧清单的标签页、或离线运行的旧版本无法收到远端停用信号，不能被即时远程中止。只有用户下次自行打开/刷新并载入新静态版本后，应用才能检查新的 `disabled` 状态并暂停相关快照。该限制遵循 REQ-051 的安全延迟更新和 REQ-082 的常规静态修复流程；不增加后端、紧急远程禁用服务或强制自动重载，也不得把本机制描述成即时远程封锁。
- 快照必须保存不可变的题目内容、判题所需快照、顺序、组卷种子、内容清单版本和独立的 `snapshotSchemaVersion`。内容清单版本说明快照基于哪个题库版本；结构版本用于读取/迁移，二者不可混用。
- 已知旧快照通过 IndexedDB 版本迁移补齐/转换为受支持结构，保留原答案和题目内容。遇到未知未来结构时，不推测转换、不覆盖原数据，暂停该记录并提供既有数据恢复/隔离路径。具体旧快照迁移步骤由实施计划根据当前数据结构定义。
- 向后兼容：当前 v1 JSON 备份中的旧进行中快照没有 `snapshotSchemaVersion`。导入时必须先按原始文件内容完成 SHA-256 完整性校验，再将已知旧快照归一为首个快照结构版本；新导出包含该字段，备份外层格式仍保持 v1。不得在校验前改写数据，也不得把未知快照版本当作旧版。

### 5.4 候选池、去重和知识覆盖（REQ-043～045）

有效候选必须同时满足：生命周期为 `active`、显式审核通过且审核记录有效、完成答案泄露检查、活动存在且 ID 一致、题型由挑战渲染器支持、课程来源在组范围内、题目标签有效，且不因 ID/活动 ID/精确内容重复而重复计数。内容指纹差异不改变此资格规则。

对每个组、每个难度分别校验：

1. 有效题量至少是该难度任务最大 `targetCount` 的两倍。
2. 候选题覆盖组要求的所有核心知识点；每个任务的必需知识点是组核心知识点的非空子集。
3. 基础两任务和进阶两任务分别共同覆盖全部组核心知识点；高阶任务的整份试卷联合覆盖至少两个核心知识点。
4. 每次模拟产出的题量、唯一题目数、题型/难度范围和知识点覆盖均满足生产组卷器约束；不能通过静默放宽约束来让模拟通过。

精确重复按规范化活动内容指纹去重，并按稳定 ID 字典序选择报告中的代表项；不自动改写或合并题目记录。候选池按去重后的有效题目计数。相似题只输出确定性提示，不自动去重、不改变题目资格，也不单独阻断 CI。首版相似候选建议限定在同一课程范围和题型内，对题干做 Unicode NFKC、空白/标点规范化，并把纯数字字面量规范成占位符后比较；算法、阈值和误报率须在试点题库上验证，报告应解释命中规则，不能伪装成语义判断。

多种子模拟对每个声明为 `released` 的任务使用至少 100 个确定性种子，种子由清单版本、任务 ID 和序号稳定生成；每个 seed 的结果均应可复现。默认值 100 是工程建议，必须在完整题库规模上测量耗时。若任何种子无法组卷或输出违反约束，该 released 组不可就绪；不得只抽查通过的种子。

### 5.5 状态报告（REQ-042、046）

每个组报告配置意图、最终状态、阻断原因、非阻断警告、按难度的目标数/有效唯一数/两倍门槛、知识点覆盖、模拟样本数和失败数。任务级报告列出每次模拟失败原因。题目级条目只含稳定 ID、字段路径、分类和指纹等必要元数据，不含题干、答案、讲解或学生数据。

状态按以下唯一规则计算：

| 声明意图 | 质量检查 | 展示状态 | 阻断发布 |
|---|---|---|---|
| `planned` | 无论题池是否已就绪 | `planned` | 不因题池尚未满足而阻断；清单结构/全局 ID 等完整性错误仍阻断 CI |
| `suspended` | 无论题池是否满足，必须提供不可用原因 | `unavailable` | 不作为发布目标；清单结构/全局完整性错误仍阻断 CI |
| `released` | 全部阻断项、两倍题池、覆盖和全部种子模拟均通过 | `ready` | 否 |
| `released` | 任一发布硬门禁未通过 | `unavailable` | 是，CI 失败 |

`ready` 只能由声明意图和共享校验规则推导，不得由 React 页面硬编码。现有应用与 CLI 应调用同一状态解析器。报告 JSON 带独立报告 schema 版本和清单内容版本；列表按稳定 ID/错误码排序，不默认写入生成时间或随机值，保证相同输入产生字节等价的核心报告。Markdown 为中文摘要。报告写到临时构建目录/CI artifact，不作为 `dist` 公开资源，不提交为第二份权威清单。

## 6. 质量门禁与退出行为（REQ-036）

- 增加单一 `npm run challenge:quality` 命令，本地与 CI 使用相同默认规则。可选参数用于指定报告目录或本地快速模拟样本数；CI 固定执行完整发布门禁，不允许通过参数降低硬门槛。
- 在现有 `Quality` 工作流安装依赖后增加题库质量步骤；保持现有单测、覆盖率、构建、浏览器测试全部启用。质量步骤不得取代现有应用/学习回归测试。
- 全局清单解析失败、版本/引用错误、重复稳定 ID、将题目标记为已审核却缺少有效审核记录、released 组阻断问题、有效唯一题量不足、知识覆盖失败或任何模拟失败均以非零退出码结束，并列出定位信息。未审核题目可以留在 planned 范围或题库中，但不能计入有效候选池。
- 指纹变化、可能相似题、planned/unavailable 的预期状态，以及被停用/弃用但未被已发布组引用的内容作为可审阅报告信息；除非另一个硬规则被违反，否则不因这些信息本身失败。
- 持续集成将中文摘要放入工作流摘要，并保存机器 JSON 与 Markdown 报告作为诊断产物。不得把报告状态写回清单或自动修改源文件。
- CI 可验证结构、组卷约束、评分代码回归和存储迁移测试；题干是否符合年龄、知识点/难度映射是否有教学意义、答案是否符合教材目标仍需按风险等级完成必要人工检查。人工检查不新增独立审核人或额外审核证明字段。

## 7. 测试与验收设计

实施遵循 TDD：先为每类规则建立失败测试，再实现最小校验。至少覆盖以下边界：

- 全局 ID 重复、跨清单 ID 碰撞、活动 ID 复用、稳定 ID 不随题干改动；缺少/错误引用和清单版本。
- `approved` 最小元数据校验、答案泄露检查、作者自审；更改内容后 `approved` 仍保留、指纹变化可见但不改变组状态或 CI 退出码。
- active/disabled/deprecated 对新组卷的资格，以及 disabled 阻止包含该 ID 的未完成快照继续、deprecated 和普通内容变化仍允许冻结快照继续。
- 相同输入产生相同 SHA-256、重复分组及代表项、相似候选排序稳定且只提示不阻断；数值变化的题目对误报样例要有边界测试。
- 每个难度 2× 门槛边界、去重后低于门槛、覆盖缺项、题型不兼容、任务/高阶整份试卷覆盖和不可能约束。
- 多种子确定性、所有种子执行、模拟任一失败即阻断；相同清单重复执行得到稳定 JSON/Markdown 核心内容。
- `planned`、`suspended`、`released + ready`、`released + blocked` 状态表；缺少暂停原因。
- 现有学习课程入口、学习进度与答题语义继续由已有回归套件保护；快照字段变更须有 IndexedDB 迁移、旧版本快照恢复、旧 v1 备份兼容、校验先于归一化及未知版本安全失败测试。
- CLI 无网络、无写源数据、不读取浏览器存储；报告不含题干、答案、讲解、个人信息或本地答题数据。

## 8. 文件影响范围（预期）

实施阶段预计触及：

- 共享挑战内容/领域模块：复用或提取结构校验、有效题池、状态解析和模拟入口；必要时将试点专用命名推广为通用接口。
- 仓库脚本与 `package.json`：只读 CLI、报告格式、命令入口及必要的 TypeScript 执行方式。
- `.github/workflows/quality.yml`：增加质量命令和报告产物，不删改现有质量步骤。
- 闯关存储数据模型：为进行中快照增加独立结构版本及相应迁移/兼容测试；不改变学习进度存储。
- 测试与中文文档：CLI/规则测试、需求追踪矩阵、测试方案、开发指南、题库变更记录说明和必要的报告样例。

不预先承诺新增第三方依赖。实施计划阶段应比较仓库已有 Node/TypeScript 运行方式后再决定脚本执行器；如需新增开发依赖，核验其许可、锁文件变更和本地/CI 一致性。

## 9. 待验证事实与风险

这些项目是实现前的仓库核查，不代表方案暂缓：

1. 全课程内容模块能否在 Node 命令环境安全、完整、可重复加载；加载器是否有浏览器全局副作用。
2. 全课程映射后的题目 ID、活动 ID 和精确内容指纹重复率；现有 14,944 道题是否足够满足经资格过滤后的每个任务两倍题池门槛。
3. 现有 `assembleChallenge()` 是否适合批量模拟，100 种子 × 全课程任务的实际耗时/内存；是否需要只做可验证的缓存，不能改变采样结果。
4. 相似题规则在语文、数学、英语及不同题型上的误报/漏报；试点外验证前只作为报告提示。
5. 当前在进行中的 v1 快照、旧 v1 JSON 备份和 IndexedDB v3 记录形态；快照 schema 字段增加后，迁移能否原样保留冻结题目和已保存首答，并保持先校验备份完整性再归一化。
6. GitHub Actions 对报告摘要和 artifact 的实际权限/保留策略，以及工作流中的质量门禁是否作为 PR 必需检查；本地规格不代表远端设置已核实。
7. CI 能验证自动规则，但不能证明人工教学检查已执行；正式发布仍按 REQ-077、REQ-076 及项目开发指南记录实际检查范围。
8. 静态更新无法立即改变已打开或离线旧页面的清单；REQ-041 的暂停仅能由载入新版本的应用实例执行，不能提供远程即时中止保证。
