# 一至六年级闯关课程扩展实施计划

> **执行说明：** 按 `superpowers:executing-plans` 逐项实施；使用 `- [ ]` 复选框记录进度。

状态：按用户指示完成复审修订后执行；复选框只表示对应任务已完成并通过该任务验证。

**目标：** 按一年级到六年级的顺序，完成上下学期语文、数学、英语的挑战组、原创候选题、逐题自审台账和发布验证。

**架构：** 继续使用 `ChallengeManifest`、课程注册表、现有领域组卷器和质量门禁。每个年级只增加教材目录中有证据的正式单元组和固定的 18 个学期阶段组；课程活动只在范围、题型和难度适配后复用，缺口用原创闯关题补足。

**技术栈：** TypeScript、React/Vite、Vitest、Playwright、Node.js 22、JSON 闯关清单、IndexedDB 不变。

**设计规格：** `docs/superpowers/specs/2026-10-25-grade-1-to-6-challenge-course-expansion-design.md`

## 全局约束

- 按年级严格从一至六年级推进；当前年级未通过全部放行条件时不进入下一年级。
- 单元组只映射正式编号且 `achievementEligible` 的课程单元；一年级语文主题单元不虚构单元编号。
- 每个单元组有 2 个基础、2 个进阶、1 个高阶任务；每难度有效、审核通过、唯一且兼容的候选池至少 30 题。
- 每个学期阶段组有 2 个基础、2 个进阶、1 个高阶任务；每任务默认 25 题、最多 30 题；每难度候选池至少是实际目标题量的两倍（默认至少 50 题，目标题量为 30 时至少 60 题）。
- 题干、提示、解释、材料、情境和反馈均为原创；每个候选题都逐题自审，作者自审不得描述为独立教育者审核。
- 题目质量沿用 `docs/curriculum/authoring-standard.md` 和 `docs/curriculum/course-content-review-rules.md` 的“学期 → 单元 → 任务 → 题目”标准；挑战题另外按 `docs/challenges/DEVELOPMENT_GUIDE.md` 检查候选池去重、题型与组卷兼容、知识点映射、稳定 ID、答案键和实际呈现。课程题台账不能替代挑战组逐题台账。
- 英语学校开设状态保持课程元数据中的“未确认”；每批题库变更按现有约定更新清单版本。新题审核指纹由指纹模块计算。`approved` 状态按 REQ-080 保留；已有审批基线的题目编辑后保留原 `approvedContentFingerprint` 以报告内容变化。尚未发布的新题在最终放行前发生修订并完成复核时，可将指纹设为最终审核内容的基线，不得据此宣称旧内容从未变化。
- 不修改现有学习 Task、学习进度、课程内容或学习交互；不增加后端、账号或在线题目服务。
- 内容指纹变化保留 `approved` 状态；严重问题按既有流程显式停用，不因普通编辑暂停发布。
- 使用当前 `vite.config.ts` 的 Rolldown 分块配置；生产构建不得出现超过 500 kB 的 JavaScript 分块警告。
- 本计划不授权提交、推送、合并或部署。

## 审查重点

- 教材版本、目录或学校开课状态未核实：该组保持计划中/不可用，来源核对归入对应年级任务。
- 课程原题超出该单元已教范围、题型不兼容或跨难度精确重复：逐题题源审计归入对应年级任务；不得把源素材盘点当成可发布资格。
- 候选题知识点标签与题目实际目标不一致：`pilotManifest.test.ts` 中的逐题知识映射断言归入对应年级任务。
- 选择、配对、分类、排序或计算题的答案键与学生实际看到的内容不一致：`pilotContent.test.ts` 全候选生产评分及组卷覆盖断言归入对应年级任务，并在该组台账逐题复核。
- 分块合并后单个 JavaScript 分块超过 500 kB，或静态课件内容影响原学习流程：该年级任务的 Vite 构建与现有挑战/学习回归检查阻止该年级放行。

## 文件职责与接口

- `src/challenges/content/pilotManifest.ts`：合并核心清单和各年级/学期/学科 JSON 片段；不改变 `mergeChallengeManifestFragments(fragments: readonly ChallengeManifest[]): ChallengeManifest` 接口。
- `src/challenges/content/pilot-manifest-grade{grade}-term{term}-{subject}.json`：追加该册新建的正式单元组、三个学期阶段组及其题目记录。一个组 ID 只能定义一次；核心清单和现有一年级数学单元 5～9 片段继续保留原组，不得在新片段中重复复制或二次合并。新片段中的题目 ID 按组、任务和候选题稳定生成。
- `src/challenges/content/grade{grade}Term{term}{Subject}Unit{unit}SupplementalActivities.ts`：存放该正式单元经题源审校后仍需的原创补题；每题包含稳定活动 ID、难度、来源单元和人工确定的知识点。
- `src/challenges/content/grade{grade}Term{term}{Subject}{Stage}SupplementalActivities.ts`：仅当阶段题源审计显示课程活动不足时，存放阶段组所需原创补题；稳定活动 ID 包含阶段、难度和序号，每题标记同册来源单元及人工确定的知识点。
- `src/challenges/content/pilotQuestionKnowledgePoints.ts`：为清单引用的课程活动和补充题提供逐题知识点映射；现有试点映射保持有效。
- `src/challenges/content/pilotContent.ts`、`qualityInputs.ts`：注册清单引用的课程与原创活动；候选活动 ID 重复或来源不一致必须失败。
- `src/challenges/content/pilotManifest.test.ts`、`pilotContent.test.ts`、`coverage.test.ts`、`qualityCli.test.ts`：校验清单片段无重复且各合并一次、题目映射、所有候选的评分/组卷、覆盖数量与五任务结构；同步更新 CLI 报告中的实际组数和片段快照列表。
- `src/challenges/content/unitLinks.ts` 与 `unitLinks.test.ts`：为每个新增且已开放的正式单元登记课程页闯关入口，逐项核对课程单元键与组 ID。
- `src/challenges/content/growthGroups.ts` 与 `growthGroups.test.ts`：将已登记的单元组和学期阶段组作为轻量元数据投影加入闯关成长索引；测试其组 ID、任务 ID 和范围与正式清单一致，并检查成长页不加载或暴露题干、答案。
- `src/challenges/content/semesterMapping.test.ts`（或现有等价测试）：按教材清单和课程注册表顺序验证前半/后半分半依据不重叠、合并后覆盖全部正式章节；没有正式编号章节时，以登记主题作为分半依据（如一年级语文）。复习和综合实践可作为补充来源，但不得改变正式章节的分界，且须在映射证据中说明；期末综合只引用该册已登记范围。
- `src/challenges/ui/ChallengeCenter.tsx` 与 `ChallengeCenter.test.tsx`：阶段卡片说明须根据前半、后半、期末显示准确描述，不把所有阶段都写成上册前四个单元。
- `docs/challenges/grade-{grade}-term-{term}-{subject}-unit-{unit}-question-review.tsv` 与 `grade-{grade}-term-{term}-{subject}-{stage}-question-review.tsv`：逐题自审证据；每个组列出其完整有效候选池的题目 ID。
- `docs/curriculum/authoring-standard.md`、`docs/curriculum/course-content-review-rules.md`、`docs/challenges/DEVELOPMENT_GUIDE.md`：本计划采用的课程内容质量基线、逐题审校规则与挑战题专属检查项；发现标准冲突时以已批准设计规格和既有 REQ 决策为准，不擅自降低题目质量门槛。
- `docs/challenges/CONTENT_CHANGELOG.md`、`ROADMAP.md`、`REQUIREMENTS_TRACEABILITY.md`：记录本年级内容变化、覆盖状态和对应证据。
- `vite.config.ts`：按年级、学期、学科拆分清单和补题代码；构建后逐块检查体积，必要时沿单元或阶段边界细分，不调整 500 kB warning 阈值。
- `tests/e2e/challenge-flow.spec.ts`：至少验证一个新单元的课程页入口和一个新学期阶段组入口可打开，且不写入课程进度。

### 每个年级批次的 TDD 与审校步骤

1. 在 `coverage.test.ts` 增加当前年级覆盖检查。年级尚未完成时，测试精确记录当前已登记组数、缺组数和未发布组数，保持日常测试通过；年级收尾时再改为完整覆盖断言。缺组测试首次按预期失败的证据记入实施台账。年级放行依据是 `coverage.test.ts` 对该年级 `missing` 与 `unreleased` 列表的零缺口断言；CLI 的 `--require-complete` 检查全课程 254/108 目标，只在六年级完成后运行，不能用作单一年级门禁。
2. 对照教材清单、课程注册表、`docs/curriculum/course-content-review-rules.md` 和 `npm run challenge:source-audit`，逐册核实教材版本/目录、正式单元与主题、阶段边界、知识点和兼容题源；排除越界或不兼容题目。
3. 添加正式单元与阶段组、题目记录、知识点映射、必要的原创补题和审校台账。稳定 ID 使用课程元数据和组卷任务路径，不复用其他题目 ID。
4. 运行针对性测试，确认当前年级覆盖断言、阶段边界、课程入口与成长索引、全部新增清单题的知识映射、生产评分与每任务组卷覆盖均通过；若有新行为或映射逻辑，必须先观察对应测试按预期失败。
5. 按课程内容分层审核规则，对候选池每道题逐题独立作答，核对题干、答案、提示、讲解、知识点、难度、年龄适配、教材范围、重复及运行时呈现；按闯关开发指南检查候选池、评分键和组卷兼容性。每个组的中文挑战台账完成并通过检查后，才将该组设为 `released`。全年级仍须通过最终放行门槛后才能开始下一年级。
6. 年级批次结束时运行 `npm run challenge:quality`（默认 100 个确定性种子）、`npm run challenge:coverage`、`npm run challenge:source-audit`、`npm run test:unit`、`npm run test:e2e`、`npm run build` 和 `git diff --check`。确认该年级无覆盖缺口、已发布组就绪、课程入口与成长索引完整、构建无超 500 kB 警告，且原学习流程/进度未回归。
7. 更新该年级内容变更、路线图和需求追踪；写明逐题自审、自动质量检查和回归验证分别覆盖的范围。完成后再进入下一年级。

`coverage.test.ts` 的仓库清单测试须随批次更新累计数字，并另外断言本批年级在 `missing.unitGroupIds`、`missing.semesterGroupIds` 和 `unreleasedGroupIds` 中均没有条目。下表为仓库累计数：一年级完成后仍包含二年级语文单元 1～2、数学单元 2、三年级英语单元 1、五年级语文单元 1 共 5 个其他年级单元组，以及二年级数学前半学期组；不是单一年级目标数。

## 年级批次

每个批次均按上学期、下学期处理；每学期内先依据目录完成语文、数学、英语的正式单元组，再建立这三科的前半、后半、期末三个阶段组。存在正式编号章节时，只按正式章节顺序等分；奇数章节前半取较少的一半、后半取余下部分。没有正式编号章节时，以登记主题顺序等分。一年级语文没有正式编号单元组，但须把主题作为分半依据纳入上下学期共 6 个阶段组。复习和综合实践可作为阶段组补充来源，但不能移动正式章节的边界；所有来源范围与教材证据写入 `mappingEvidence`。

### 任务 1：一年级闯关内容

**文件：** 上述一年级清单片段、补题模块、映射/加载/测试文件，以及一年级全部组的中文审校台账和挑战文档。

**接口：** 输入现有一年级上册数学正式单元 1～9 题库和其台账；输出一年级全部 29 个正式单元组、18 个学期阶段组，每组五个任务。完成后覆盖统计为一年级 29/29 个单元组、18/18 个阶段组。

一年级分半映射先按教材清单固定为：上册语文主题 `unit-01`～`unit-04` / `unit-05`～`unit-08`，数学正式单元 `unit-01`～`unit-04` / `unit-05`～`unit-09`，英语正式单元 `unit-01`～`unit-03` / `unit-04`～`unit-06`；下册语文主题 `unit-01`～`unit-04` / `unit-05`～`unit-08`，数学正式单元 `unit-01`～`unit-04` / `unit-05`～`unit-08`，英语正式单元 `unit-01`～`unit-03` / `unit-04`～`unit-06`。英语 Revision 和数学综合实践不参与分半计数；如纳入阶段候选，须作为额外来源列明，不能改变上述边界。
