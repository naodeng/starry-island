# 闯关全课程覆盖盘点与 V1.0 发布门禁实施计划

> **执行说明：** 按已确认的 Native 方式，由当前会话逐项实现；每个代码步骤先写回归测试并确认失败，再完成最小实现。

**目标：** 依据课程清单和闯关清单，生成覆盖 254 个正式单元、108 个学期阶段组和 540 个学期任务的可追踪报告，并在 V1.0 发布检查中阻止不完整覆盖。

**架构：** 新增纯函数分析课程目录与闯关清单，输出机器可读 JSON 和中文 Markdown。默认模式报告缺口但不阻断渐进式试点；显式完整性模式要求所有正式单元组和学期阶段组已发布且每组含规定的五个任务。常规质量工作流生成报告，V1 标签触发的发布检查启用完整性门禁。

**技术栈：** TypeScript、Node.js、Vite SSR、Vitest、GitHub Actions；不增加运行时依赖或后端。

**依据：** [PRD](../../challenges/PRD.md)、[迭代路线图](../../challenges/ROADMAP.md)、[需求追踪矩阵](../../challenges/REQUIREMENTS_TRACEABILITY.md)。

## 全局约束

- 仅把 `type=unit` 且 `achievementEligible=true` 的正式编号单元计入单元覆盖数。
- 学期范围固定为 6 个年级 × 2 个学期 × 3 门学科 × 3 个阶段；每组两项基础、两项进阶、一项高阶。
- 只读消费 `curriculum-manifest.json` 与闯关发布清单；不得自动生成或审核题目。
- 报告必须区分已登记、已发布、缺失和结构不完整；缺失题目不得被解释为内容已审核。
- 工作流中渐进式分支执行非阻断盘点，`v1.*` 标签执行严格覆盖门禁；外部 GitHub Actions 结果仍须在线验证。
- 中文过程文档；不得修改现有课程 Task、学习进度或课程答题行为。

## 审查关注点

- 36 个组合包含暂时没有正式编号单元的年级/学期/学科时，仍须生成学期阶段组期望项。
- `planned` 或 `suspended` 不能被记为 V1.0 已发布覆盖。
- 重复 ID、缺失 `curriculumUnitKey`、学期组跨课程引用和任务难度分布错误不能通过完整性检查。
- 渐进式质量工作流不能因 V1.0 尚未完成而阻断当前试点开发。
