# 本地数据模型

状态：闯关数据使用独立 IndexedDB 保存。当前数据库结构版本为 4：版本 2 加入错题仓库，版本 3 加入异常记录隔离仓库，版本 4 为进行中的答题快照增加结构版本并迁移有效旧快照。支持从版本 1、2、3 升级并保留有效数据，也会在读取前校验现有记录、隔离异常记录。隔离记录可由用户明确选择后导出原始内容，也可对通过白名单校验的已知格式逐条预览和安全恢复。本机 JSON 导出、SHA-256 校验、导入预览、安全合并、可选携带主题与语音偏好、分级清除、24 小时恢复点、安全恢复、统一错误分类和手动诊断导出均已在本地实现。配额错误下的待保存答案保护与安全重试提示已实现；真实配额恢复和浏览器驱逐处理仍未实现。

## 与现有学习数据的边界

现有学习进度保存在 `china-study-progress-v1`，闯关仓库不会读取或写入该存储。闯关数据保存在独立的 IndexedDB 数据库 `starry-island-challenges`。

### 历史奖励与内容修订

最佳成绩和 `everPassed` 在后续较低成绩后仍保留；任务组徽章从曾通过状态推导，不会因后续挑战成绩降低而熄灭。内容指纹记录题目变化，但 REQ-080 要求编辑时保留现有 `approved` 状态；不得把旧审核记录描述成对新内容的重新审核，也不得仅因编辑自动暂停挑战。

本地不保存完整作答历史，因此答案或评分修订通常无法可靠重算每位用户的历史成绩。只有在有确定、逐项匹配的作答证据时才允许补偿；证据不足时保留原成绩与奖励，不推测性撤销或增加。

## 已实现的 IndexedDB 记录

| 对象仓库 | 主键 | 保存内容 |
|---|---|---|
| `attempts` | `taskId` | 每个任务一条未完成挑战，含冻结题目快照、种子、当前题序号、首答、用时和单调递增的修订号 |
| `taskProgress` | `taskId` | 最佳和最近答对/总题数、完成次数、是否曾通过、更新时间和修订号 |
| `challengeMeta` | `key` | 最近三次已完成挑战的题目 ID（`recent-question-ids`），以及最多一条 24 小时恢复点（`recovery-point`） |
| `wrongQuestions` | `questionId` | 首次答错时的题目快照、累计答错次数、最近答错时间、连续答对的已完成挑战次数、最近答对时间（新增字段，可选）及可选掌握时间 |
| `quarantinedRecords` | 自增编号 | 结构校验失败的原始记录、来源仓库和键、隔离时间及原因代码；不参与闯关、成绩、普通备份或恢复点合并 |

对应类型 `ChallengeAttempt`、`ChallengeQuestionSnapshot`、`ChallengeResult`、`TaskProgress` 和 `WrongQuestionRecord` 定义在 `src/challenges/domain/types.ts`。仓库接口位于 `src/challenges/storage/repository.ts`，IndexedDB 实现在 `indexedDbRepository.ts`。

### 写入与完成规则

- 新挑战从修订号 0 且无答案开始。每次确认首答只增加一个修订号，并前进一道题。
- 写入使用 IndexedDB 事务。旧修订号会被拒绝；答案不能修改，也不能为非当前题目新增。
- 如果写入调用可能已提交但没有收到确认，闯关页会比较数据库中的完整快照与预期快照。修订号相同但答案不同仍视为冲突；只有修订号相同并不足以证明本页答案已经保存。
- 完成时使用正式答案检查器重新计算分数并验证进度更新；然后在同一事务中更新错题记录、任务进度和最近题目 ID，并删除未完成快照。事务失败时这些变更一起回滚。
- 只有完成的挑战才会更新错题本。丢弃、未完成或仅提交部分答案的挑战不计入错题次数或掌握进度。
- 第一次答错会保存该次挑战使用的题目快照。之后再答错会增加次数、更新最近答错时间与题目快照，并清除掌握状态。题目在之后的某次已完成挑战中答对，会增加连续答对次数；两次不同的已完成挑战连续答对后标记为已掌握。已掌握后继续答对不会增加计数；再次答错会重置连续答对次数和掌握状态。
- 错题记录只保存逐题练习所需的信息，不保留完整的挑战提交历史。答题过程中的错题讲解仍在本次完成结果页显示；刷新或离开结果页后，错题本使用此前保存的题目快照与讲解。
- 界面只在 IndexedDB 确认答案写入后前进。写入失败会暂停挑战，并提供重试或退出操作。
- 丢弃会删除未完成快照，不更新成绩、完成次数、最近题目记录或错题本。

仓库测试使用仅开发依赖 `fake-indexeddb`，覆盖两个共享数据库连接争抢同一修订号、完成事务原子性、数据库结构从版本 1、2、3 升级到版本 4，以及无效答题、进度、错题和最近题目记录的原子隔离。浏览器端保存/刷新恢复与页面关闭后的 Web Locks 接管另有测试。组件测试注入配额异常，验证答案保护和重试提示；它不模拟真实配额耗尽。浏览器进程崩溃、实际配额耗尽和浏览器驱逐仍未专项验证。

### 结果页学习建议

薄弱知识点和现有学习任务的关联在结果页从本次完成挑战快照、试点知识点标签和课程数据即时计算，不另存推荐历史或课程进度。错题命中现有课程活动时沿用该活动的任务归属；闯关补充题按相同知识点关联最聚焦的现有学习任务。点击复习入口只改变当前路由，不会自动开始课程或标记任何学习场次完成。

### 闯关成长统计

成长页仅读取 `taskProgress` 并根据当前已登记挑战组即时推导累计完成次数、曾通过任务数、已点亮组徽章和各组通过进度。不创建汇总记录、不写入学习进度，也不推算逐日趋势、连续学习天数或已经不在当前清单中的组徽章。

### 本机备份导出（格式版本 1）

导出前在同一个只读 IndexedDB 事务中读取 `attempts`、`taskProgress`、最近三次挑战的原始题目列表和 `wrongQuestions`，避免得到跨对象仓库混杂时点的快照。文件格式标记为 `starry-island-challenge-backup`，包含版本号、导出时间、闯关数据和 SHA-256 摘要；用户主动勾选后可额外包含顶层 `preferences`（主题 `system`/`light`/`dark` 与语音开关）。可选字段受摘要保护；不含该字段的旧版格式版本 1 备份仍可导入。课程进度不会进入备份。

SHA-256 仅用于检测传输或保存过程中的意外损坏，不证明文件来源，也不能阻止有人修改内容后重新计算摘要。导入文件限 10 MB；先校验版本和原始字段结构，再对未经修改的载荷校验摘要。摘要通过后，才将已知旧快照（缺少 `snapshotSchemaVersion`）归一化为当前版本；未知快照版本拒绝导入。之后展示预览，只有用户确认后才写入。

### 手动诊断导出（格式版本 1）

闯关中心仅在用户点击“手动导出脱敏诊断信息”后生成 JSON 下载，不自动发送或上传。报告字段白名单为格式标识、报告版本、生成时间、应用版本、IndexedDB 结构版本、IndexedDB/Web Locks 能力布尔值，以及未完成答题数、进度记录数、最近完成挑战组数和错题数。实现从只读快照取汇总数，再由显式字段构造报告；不写入题目/答案/任务 ID、姓名、浏览器标识、网址、学习进度或原始错误信息。报告模式和验证位于 `src/challenges/domain/diagnostics.ts`。

### 错误分类与恢复提示

`src/challenges/domain/errors.ts` 将已知异常及其嵌套原因分类为跨标签页冲突、设备存储空间不足、存储暂不可用、挑战状态不匹配或未知错误。界面只显示固定中文恢复说明，不把数据库/浏览器内部异常文本展示给儿童；未知错误使用当前操作提供的安全兜底文案。配额错误时明确提醒释放设备存储空间后重试，不要清除此网站的数据。首答未写入时只在当前页面内保留答案；返回任务列表或重新读取已保存进度前，需要确认放弃该答案。自动保存仍以 IndexedDB 确认成功为前进条件，错误分类不改变事务结果，也不会自动重试、删除记录或修改课程数据。

安全合并规则：同一任务的本机未完成答题优先；存在本机未完成答题时，该任务成绩暂缓合并，完成答题后可再次导入以补齐。其他任务成绩保留比例更高的最佳成绩，最近成绩取更新时间较新的记录（时间相同时取最近得分较高者），是否曾通过取两端并集，完成次数和修订号取较大值，避免重复导入虚增。错题次数取较大值，题目快照取最近答错的版本，掌握状态按最近答错、答对或掌握事件取值；新增的可选 `lastCorrectAt` 用于比较掌握事件，旧记录缺少该字段时回退到其最近答错时间。最近三次题目记录在缺少跨设备时间戳时以本机顺序优先。重复导入保持幂等。

由于产品不保留完整作答历史，无法识别两个设备上互不重叠的完成次数；为避免重复累计，取较大完成次数可能低估合并后的真实总次数。导入预览单独展示备份内的主题和语音偏好，默认不应用；用户明确勾选后，只有闯关记录的 IndexedDB 合并成功才更新偏好 Provider。偏好不参与成绩合并，课程进度始终不读取、不写入。

### 分级清除与恢复点

数据管理提供三种清除范围：清除未完成答题；清除错题本；清除全部闯关数据（未完成答题、成绩、最近题目记录和错题本）。每种操作都先展示影响范围和二次确认；清除全部还要求输入“清空闯关数据”。课程进度和个人设置不属于清除范围。若当前没有可清除记录，则不创建新快照，也不替换已有恢复点。

实际清除在一个覆盖四个数据仓库的 IndexedDB 读写事务中读取完整本机快照、写入恢复点并删除所选数据。恢复点使用 `challengeMeta` 中固定主键 `recovery-point`，包含格式版本、创建时间、到期时间和四类闯关数据；有效期固定为 24 小时，因此最多只有一个有效恢复点。新清除操作会在同一事务内覆盖旧恢复点；如果新快照写入或清除失败，事务整体回滚，旧恢复点和原有数据仍保留。

恢复前验证恢复点结构和有效期，在同一个事务中将快照按安全合并规则并入当前记录，再删除恢复点。成功提交后恢复点只消费一次；事务失败时恢复点和当前记录保持不变。恢复期间若本机存在同任务未完成答题，优先保留本机答题并暂缓该任务成绩；只要仍有成绩待恢复，恢复点会保留，待答题完成后可再次恢复。恢复点只用于有限撤销，不替代用户导出的备份，也不能抵御浏览器驱逐或设备损坏。

## 版本与内容指纹

数据库结构版本 1 创建 `attempts`、`taskProgress`、`challengeMeta` 三个对象仓库；版本 2 新增 `wrongQuestions`；版本 3 新增自增主键的 `quarantinedRecords`；版本 4 不增加对象仓库，而是在升级事务中为结构有效且缺少版本字段的进行中快照补入快照结构版本 `1`，也迁移 24 小时恢复点内有效的旧快照。数据库升级不删除或重写其他业务字段。格式错误或版本未知的记录不猜测转换，交由后续读取校验和隔离流程处理。仓库首次读取前会在单个读写事务中校验答题、进度、错题、最近题目记录和恢复点；无效记录先写入隔离仓库，再从活动仓库删除。两步同属一个事务，若事务失败，原记录仍保留。

`ChallengeAttempt.snapshotSchemaVersion` 标识未完成作答快照的字段结构，当前值为 `1`；`contentManifestVersion` 仍用于标识组卷时的题库内容版本，两者互不替代。旧格式版本 1 JSON 备份仍受支持：先校验原始载荷 SHA-256，再归一化已知旧快照；未知版本不会被改写或导入。

题目使用规范化 JSON 与 SHA-256 指纹。题库清单保留审核时指纹，验证器报告当前内容变化。根据 REQ-080，指纹变化不会自动清除 `approved`；指纹用于变更追踪，并不表示新文本已经重新审核。

恢复活动挑战时，页面先取得任务级写入租约并重新读取 IndexedDB，然后在任何续答或“答案已齐全”自动补记成绩逻辑之前检查快照题目 ID 是否命中当前已载入清单的显式停用记录。命中后释放租约，保留原快照且不写答案、不计成绩；未命中时继续使用冻结快照。组状态为 `unavailable` 时仍可恢复已有快照，但不能创建新挑战。静态页面、已离线页面或尚未刷新页面无法获知后续发布的停用状态；没有远程禁用服务，也不会自动重载。

## 隔离记录安全恢复

闯关中心只展示隔离数量。用户主动打开“检查可恢复记录”后，仓库按隔离自增主键倒序分页，每页最多 50 条；页面摘要不含原始记录，题目、选项、答案、讲解和原始错误文本不会进入界面。用户选中记录后才生成只读预览，展示目标闯关仓库、目标键和唯一允许的结构转换。不可恢复记录显示固定中文原因，没有确认入口，原始导出仍可用。

只有来源仓库与原因代码属于已知组合、记录完整有效（或符合既有旧快照迁移）、业务键与原仓库键一致、结构可稳定比较且目标键空闲时才可恢复。当前唯一允许的新转换是给已知旧版进行中答题快照补入 `snapshotSchemaVersion: 1`；恢复点内的旧快照只复用已有归一化函数。未知字段/版本、缺少关键数据、过期恢复点、未知来源和已占用目标均保留原隔离行；系统不补造答案、不重算成绩、不覆盖或合并目标记录。

预览令牌只保存在当前 Repository 实例内存中，有效五分钟且每个实例最多一个。用户确认后，仓库在覆盖隔离仓库与目标仓库的单个 IndexedDB 读写事务中重新读取并比较隔离行、重跑资格检查、确认目标仍空闲，然后以禁止覆盖的写入方式保存目标记录并删除对应隔离行。事务提交前不报告成功；冲突、过期预览或写入失败会保留隔离原文。确认尝试会消费该令牌，失败后需重新读取和预览。

该能力不升级数据库结构版本。`getQuarantinedRecords()` 仍是原始本地导出的唯一数据源，隔离 JSON 继续保持格式版本 `1`，不包含内部隔离主键或预览令牌；普通备份和脱敏诊断仍不包含隔离原文。当前仓库测试只证明合成样例的处理行为，不表示用户设备上存在可恢复记录，也不提供任意损坏数据的自动修复。

## 尚未实现：其他数据修复

- 真实存储配额恢复和浏览器驱逐处理。

浏览器可能驱逐本地数据，当前 24 小时恢复点也不能保证数据永远保留；浏览器存储配额不足时，清除会失败并依赖事务回滚保留旧数据和旧恢复点。答题写入遇到配额错误时，页面可安全重试或确认后重新读取，但不会自动释放空间，也不能保证恢复已被浏览器驱逐的数据。产品完整决策见[产品需求文档](PRD.md)。

## 隐私边界

当前闯关数据保存在用户当前浏览器中；没有新增账号、服务器、追踪器或闯关诊断上传。本地优先实现不等于已经满足任何法律合规要求。
