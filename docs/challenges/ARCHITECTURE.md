# 闯关系统架构设计

状态：本文区分当前本地实现与尚未交付的产品架构。应用仍是静态 React/Vite SPA；没有增加后端、数据库服务器或在线 AI 服务。

## 系统边界

现有课程路由、答题校验、进度、成就、提示、重试反馈和声音属于学习流程。闯关模式使用独立路由、页面编排及 IndexedDB 持久化，复用兼容的答题控件和正式答案检查器，但不改变现有学习交互。闯关题目朗读只在用户点击后读取当前题干，沿用现有语音开关，只选择设备本地中文语音；不朗读选项、答案或讲解，也不调用网络语音服务。提交答案、页面离开或关闭语音时会停止朗读。

当前试点包括二年级数学单元 2、二年级数学前半学期和三年级英语单元 1 三个组。范围、来源映射、内容证据和限制见[试点内容审计](pilot-content-audit.md)。错题本和成长统计覆盖当前登记的试点题池，不代表其他年级和学科已完整接入。成长统计读取 `taskProgress`，在内存中推导累计完成、曾通过任务、当前登记组徽章和组内进度，不增加持久化数据。本机备份导出在一个只读 IndexedDB 事务中读取四类闯关记录，用户主动选择后可附带主题和语音偏好，生成带 SHA-256 完整性校验的版本化 JSON。导入将偏好单独预览且默认不应用，只有闯关数据安全合并成功后才调用 Provider 更新。诊断导出复用同一只读快照，但只将允许的记录数量写入手动下载的 JSON；不包含题目、答案、身份、精确任务 ID、网址或课程数据，也不发起网络请求。

## 组卷流程

1. 读取任务定义、来源范围、难度、必需知识点和目标题量。
2. 仅保留生命周期为 `active`、已登记审核、已通过答案泄露检查、类型兼容且唯一的候选题。
3. 每个难度题池至少达到目标题量的两倍，并覆盖每个必需知识点；条件不满足时明确失败。
4. 使用确定性种子生成可复现的候选顺序；尽量避开最近三次完成挑战中的题目，但不得因此破坏知识点覆盖。
5. 保存选中题目的内容快照、答案评分来源、顺序、清单版本和组卷种子。

每道题只登记实际考查的知识点。高阶任务要求整份试卷至少覆盖两个核心知识点，不要求每道题都同时考查多个知识点。组卷测试会使用真实试点题池检查所有已登记任务。

一题可以覆盖多个知识点，因此知识点数多于目标题数本身不代表无法组卷；只有生产覆盖搜索无法找到满足条件的题目组合时才判定失败。同一清单内的 `taskId` 必须全局唯一，因为路由查找和 IndexedDB 的答题/进度主键都按任务 ID 工作。组 ID 和任务 ID 必须符合闯关路由格式；路由解析和清单质量校验共用 ID 校验函数，避免报告就绪但页面无法打开。闯关专用补充题显式登记 `sourceUnitId`，加载器不从清单中“第一个单元组”推测来源。

## 薄弱知识点与学习任务关联

结果页只统计本次答错题快照上的知识点标签，按答错题数从多到少展示，并给出对应复习入口。若错题来自现有课程活动，优先关联该活动所在的学习任务；若错题来自闯关专用补充题，则从同一来源单元中选择知识点标签匹配且覆盖范围最集中的现有学习任务。题目标签由试点清单提供，页面显示使用中文名称。

学习任务引用在加载课程和试点清单时从现有课程数据生成，仅保存在当前页面内存，不写入 IndexedDB 或课程进度。点击入口只打开已有任务页；闯关结果、星级和错题记录仍使用独立的闯关存储。

## 状态与持久化

一次挑战从可开始状态进入 `in-progress`，之后完成或丢弃。每道题的首答先通过 IndexedDB 修订号校验保存，再推进到下一题。若写入响应不明确，只有数据库中完整快照与预期快照完全相同时，闯关页才将其视作自身提交；仅匹配修订号不够。完成时验证已保存快照，并在一个事务内更新最佳/最近/次数/是否通过的进度、最近题目 ID、错题本，然后删除活动快照。未完成和已丢弃挑战均不计入成绩或错题掌握状态。

数据库 `starry-island-challenges` 当前结构版本为 4：版本 1 创建答题、进度和元数据仓库；版本 2 新增错题仓库；版本 3 新增异常记录隔离仓库；版本 4 在升级事务中迁移有效进行中快照及 24 小时恢复点内的旧快照。损坏记录和未知快照版本不猜测转换，留待读取校验后隔离。活动答题快照还必须包含合法难度，且题目快照中的难度必须与答题难度一致；备份导入、旧快照迁移和数据库有效记录读取共用此校验。其他升级仍按旧版本依次应用迁移；仓库首次操作前会在一个读写事务中验证活动答题、进度、错题、最近题目记录和恢复点；无效记录原样复制到隔离仓库并从活动仓库移除，事务提交后才对外提供读取结果，失败时事务回滚并保留原数据。隔离记录不进入普通备份或成绩计算；闯关中心展示数量，用户明确选择后可导出包含原始内容的本地 JSON。该导出可能含题目和作答信息，不会自动上传。错题以稳定 `questionId` 为键；答错时保存题目快照和累计次数，只有完成挑战才更新。之后在两次不同的完成挑战中连续答对，即标记为已掌握；再次答错会重置掌握状态。

每个新建的未完成挑战保存 `snapshotSchemaVersion: 1`；它只标识记录结构，和记录题库内容版本的 `contentManifestVersion` 分开。旧格式版本 1 备份先按原始载荷校验 SHA-256，之后才能把已知的无版本快照归一化；未知快照版本拒绝导入。恢复时在任务写入租约内重新读取活动快照，并先检查当前已加载清单显式停用的题目 ID，再决定继续恢复或自动完成。命中停用题时释放租约，原快照不变，不记录成绩。即使任务组当前不可用，只要已有快照未命中停用题，仍按冻结快照恢复；没有快照则禁止新开。检查仅基于页面当前已加载的清单，静态应用中的旧标签页或离线页面不会收到新发布的远程停用状态，也不会被自动重载。

静态应用不注册 Service Worker，也不会因检测到新版本而强制重载当前页面。更新后的代码在用户下一次自行打开或刷新页面时载入；闯关在每题前先确认答案写入 IndexedDB，因此刷新后可以恢复原题目快照、顺序和已锁定答案。当前没有单独的应用内更新提醒或等待安装界面。

闯关题卡的密度只根据挑战组 `definition.grade` 推导：1～2 年级使用低密度，3～4 年级使用中密度，5～6 年级使用高密度；无效年级回退到中密度。变化限于题干卡片的字号和留白，不修改学习页面、答题控件、本机记录或主题颜色。

修订号冲突会拒绝过期写入。浏览器支持 Web Locks 时，闯关页会先获取任务级独占锁、重新读取 IndexedDB，并在挑战期间持有该锁；其他页面等待当前页面关闭或完成后再读取最新状态。没有 Web Locks 的浏览器继续使用修订号检查。备份导入先校验结构和 SHA-256，再读取本机快照计算预览；确认后在一个读写事务中重新比对完整快照并合并，若预览后本机数据变化则拒绝写入。合并过程中保留本机未完成答题及该任务成绩，避免干扰正在进行的答题。SHA-256 校验可检测意外损坏，不证明文件来源或防止人工改写。数据管理将分级清除、恢复点写入和所选数据删除放在同一事务中；恢复时再次校验有效期，在单个事务内安全合并并于全部恢复成功后消费恢复点。存在进行中的同任务答题时暂缓成绩并保留恢复点。

闯关界面通过 `classifyChallengeError()` 将跨页冲突、存储空间不足、存储不可用、状态不匹配和未知错误映射为不暴露内部异常文本的中文说明及建议操作。调用方按操作保留必要的上下文兜底提示；不自动重试写入，也不绕过修订号或事务校验。

记录字段和未保留完整答题历史的规则见[本地数据模型](DATA_MODEL.md)。

## 题库质量命令与发布门禁

`scripts/challenges/quality.mjs` 使用现有 Vite 依赖的中间件模式加载 `qualityInputs.ts` 和 `qualityReport.ts`，并关闭 HMR 和 WebSocket 监听，不打开网络端口，也不访问网络。输入加载器只读取声明式挑战清单及其引用的课程/补充题数据；命令不写回清单、审核状态、指纹或浏览器存储。质量报告输出至 `.quality-reports/`，不进入静态站点资源。输入解析或加载失败时也会写出本次失败的 JSON 和中文 Markdown 诊断报告，含错误阶段、错误码及可用的字段路径，并覆盖旧报告，避免把上次的成功结果误当成本次结果。

`qualityReport.ts` 复用应用使用的清单解析、状态推导、精确重复分析和生产组卷器。每个 `released` 任务按清单版本、任务 ID 和序号构造确定性种子，默认模拟 100 次。全局完整性问题和已发布组的候选池、覆盖或模拟失败会阻断门禁；`planned` / `suspended` 组不运行发布模拟，题池不足不会阻断其他就绪组。相似题与未阻断的内容状态变化只作为提示。

报告 schema 版本为 1，包含总体通过状态、阻断项与提示、组/任务状态、分难度的目标题量/有效唯一题量/覆盖统计、模拟样本数、指纹变化、精确重复组和相似题 ID。报告不含题干、答案、讲解、学生数据或浏览器数据。相似题只提供人工审阅线索；自动门禁不能替代题目正确性、年龄适配和教学映射审核。

本地运行 `npm run challenge:quality` 会生成确定性的 JSON 和中文 Markdown。GitHub Actions 在安装依赖后执行相同的默认门禁；若质量检查失败，该步骤仍保持失败，后续回归会在依赖安装成功且工作流未取消时继续运行。摘要与报告上传使用始终执行条件，并显式包含隐藏报告目录。当前分支的工作流配置与本地命令已实现；远端 Actions 只有在推送后实际运行才能作为验证证据。

## 静态构建与分块提示

路由模块不静态导入闯关界面或试点题库清单。挑战页面与课程单元按需加载。完整课程清单仍会作为单独的初始 JavaScript 分块加载，相关 Vite 配置已消除超过 500 kB 的单块构建提示，但没有实质降低初始 JavaScript 总传输量。构建实测及两者区别见[仓库现状基线](REPOSITORY_BASELINE.md)。
