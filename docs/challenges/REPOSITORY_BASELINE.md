## 已核实的应用与课程事实

- 产品为 React 19 / TypeScript / Vite 8 静态单页应用，目标部署平台为 Cloudflare Pages；Node 版本由 `.node-version` 固定。
- `npm run build` 执行 `tsc -b && vite build`。当时持续集成工作流覆盖安装、单元测试、覆盖率、构建和 Playwright Chromium；`package.json` 没有单独的代码检查脚本。
- `src/content/curriculum.ts` 和模块化课程目录是课程内容来源；`src/content/curriculum-manifest.json` 是同步导入的目录与进度索引，不是闯关题目审核清单。
- 课程清单包含 6 个年级、36 个教材条目、311 个课程目录条目、1,868 个学习场次 ID（基础 624、进阶 622、高阶 622）。其中 254 个条目为当前登记的正式编号且可计成就的单元，另有 57 个主题、复习或综合实践条目。不能简单按 311 个条目估算 V1.0 闯关单元范围。
- 课程共有 14,944 道运行时题目（v0.3.0 发布记录）。这只是存量数量，不表示这些题目具备稳定的闯关题目 ID、题目级知识点/学期阶段映射、闯关题型适配或闯关审核状态；有效候选题池数量当时未知。
- 课程只有单元级 `sourceTopics`；当时没有题目级知识点标签、学期前半/后半映射、闯关发布清单或闯关审核台账。组卷覆盖、2 倍有效题池和 540 项交付所需的补题量仍需单独审计。
- 学习进度保存在 `china-study-progress-v1`，当时数据结构版本为 3，含已完成学习场次 ID 与可选学习起点。设置学习起点会按现有规则替换其后的本地进度。主题与声音偏好使用独立键。
- 路由、学习答题、学习进度和成就属于现有学习流程。闯关实现应新增隔离的领域状态和界面流程，不能把闯关答题语义混入现有学习任务，也不能以闯关数据结构覆盖学习进度。

## 构建分块问题

本地 `npm run build` 当时成功，但输出了以下告警：

```text
dist/assets/index-f2QQNK82.js  607.74 kB │ gzip: 113.94 kB
```

构建产物审计显示，最大单一输入来源为 `src/content/curriculum-manifest.json`：文件大小 469,129 字节，打包后贡献约 341,657 字节。该课程清单被 `src/app/router.ts`、`src/storage/progress.ts` 和成就模块同步依赖，因此会随初始应用加载。拆分前 `vite.config.ts` 未设置 JavaScript 分块策略。

### 优化结果与后续方案

1. **本地已采用：单独输出课程清单分块。** 使用 Vite 8 / Rolldown 的 `build.rolldownOptions.output.codeSplitting` 将 JSON 模块分到具名 JavaScript 分块，并保持同步模块语义。2026-10-21 的构建数据：入口分块为 `292.36 kB`（gzip 压缩后 `86.90 kB`），课程清单分块为 `316.56 kB`（gzip 压缩后 `26.83 kB`），按需加载的 ChallengePage 分块为 `189.41 kB`（gzip 压缩后 `31.07 kB`）；构建不再出现超过 500 kB 的 JavaScript 分块提示。入口和课程清单仍属于初始依赖，gzip 压缩后合计约 `113.73 kB`，初始传输量没有实质下降。
2. **进一步减少首屏数据加载：** 分离轻量目录索引和学习场次/成就元数据，并将当前同步依赖改为按需或异步读取。首页、路由校验、存储解析和成就摘要目前同步依赖完整课程清单。该方案会改变初始化与数据校验边界，应另行设计和评审。

方案 1 已按用户确认应用于工作区，没有提高 `chunkSizeWarningLimit`。如后续目标包含降低首屏传输量，应单独设计方案 2。不得将调高 `chunkSizeWarningLimit` 当作性能优化；在验证模块顺序以及路由/进度回归之前，不应调整拆分策略。

实现参考：[Vite 生产构建指南](https://vite.dev/guide/build)说明 `build.rolldownOptions.output.codeSplitting`；[Rolldown 代码分块文档](https://rolldown.rs/reference/OutputOptions.codeSplitting)说明分组配置，并提醒手动拆分可能改变副作用执行顺序。Rolldown 的 `maxSize` 是目标值，不是硬上限。
