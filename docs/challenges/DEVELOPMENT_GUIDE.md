# 闯关系统开发协作指南

本文是闯关子系统的协作指南，不会覆盖仓库根目录 `AGENTS.md`。仓库规则和用户当前明确要求优先；本文只补充闯关功能的约束。

## 目标

在不改变现有学习任务语义、不删除学习进度的前提下，实现独立的闯关子系统。

## 开发规则

1. 修改闯关功能前，阅读仓库 [`README.md`](../../README.md)、本文档、[方案入口](README.md)、[产品需求文档](PRD.md)、[决策冲突与待验证事项](DECISION_CONFLICTS.md)、[仓库基线](REPOSITORY_BASELINE.md)及[需求追踪矩阵](REQUIREMENTS_TRACEABILITY.md)。
2. 先检查当前仓库，不要臆测路径、数据形状、拉取请求合并状态或依赖情况。
3. 遵循 TDD：先写失败测试，再实现最小行为，最后整理代码；每项行为变更都要有适当的测试。
4. 保持本地优先和静态部署；未经明确批准，不添加后端服务。
5. 组卷和测试使用确定性种子。清单内 `taskId` 必须全局唯一；知识点可由同一道题覆盖多个，是否可组卷由覆盖搜索判断。不得绕过知识覆盖检查或发布质量门禁。
6. 数据库升级时保留未完成的闯关快照与已有数据；迁移失败不得覆盖原数据或学习进度。
7. 不得弱化 Q78～Q84 已确认决定：不得重新要求独立审核、因内容编辑自动撤销审核、增加紧急远程控制服务或应用内通知。
8. 避免收集学生敏感信息。诊断导出必须遵循字段白名单。
9. 任何影响行为的修改都要更新需求追踪矩阵和发布记录。
10. 不得只凭方案文档声称功能完成；必须通过测试并核对验收条件。

## 内容变更风险分级

REQ-077 已确认采用三级风险。以下等级示例和检查范围是工程实施约定，用于落实该决定；它们不是新的产品规则或额外批准门槛。每个包含题库变化的拉取请求须标注风险等级和理由。风险分级用于选择检查范围，不改变审核状态，也不要求作者之外的独立审核人。

| 等级 | 典型变化 | 必要检查 |
|---|---|---|
| 低 | 不改变答案、知识范围和挑战引用的文字修正；仅影响一个题目或单元的非评分文案 | 核对改动上下文、中文表达和年龄适配；运行题库清单校验及相关测试 |
| 中 | 修改题意、提示、讲解、难度标签、知识点标签或候选池；影响范围能从清单确定 | 低风险检查；检查每个引用该题的挑战任务、答案和覆盖关系；记录风险理由和实际检查结果 |
| 高 | 修改答案键/判题语义、稳定 ID、生命周期、共享题型控件、评分逻辑或数据结构；影响多个学科/年级；或处理已确认的严重错误 | 明确完整影响范围，执行全量内容与自动回归门禁，并进行必要的人工教学检查；严重问题按 REQ-082 手动禁用后走常规静态发布 |

若无法确认引用范围或风险等级，按高风险处理。作者可自审；高风险仍须完成必要人工检查，但不得借此要求独立审核者、额外审核证明字段或在编辑时自动撤销 `approved`。当前分支的 CI 配置包含题库质量门禁、单测、覆盖率、静态构建和浏览器测试；远端工作流尚未因本分支变更而运行。这些自动检查不替代人工教学检查。拉取请求可简述检查范围，但不要求另附审核证明。

## 题库质量命令

修改挑战清单、审核元数据、候选题或任务覆盖时，在本地运行：

```sh
npm run challenge:quality
```

命令默认使用 100 个确定性种子，输出 `.quality-reports/challenge-quality-report.json` 和中文 Markdown 报告。命令关闭 Vite 的 HMR 和 WebSocket，不打开监听端口，也不访问网络。可用 `--report-dir <目录>` 指定输出位置；本地定位问题时可用 `--seed-count <数量>` 缩短模拟，例如 `npm run challenge:quality -- --seed-count 5`。在 `CI` 环境中，低于 100 的种子数会被拒绝；快速诊断不能代替完整门禁。清单解析或输入加载失败时会生成含错误阶段、错误码和可用字段路径的本次诊断报告，并清除旧的成功报告。报告目录已加入忽略规则，不应作为题库事实源提交。

退出码 `0` 表示当前清单中的已发布组通过自动门禁，`1` 表示发现全局完整性或已发布组阻断问题，`2` 表示参数、加载或报告写入失败。报告还记录计划/暂停组状态、按难度的有效唯一题量和知识点覆盖、模拟结果、指纹变化、精确重复及相似题提示。相似题提示不自动删题；门禁通过也不证明教学正确性、年龄适配或已完成教学审校。工作流摘要和 JSON/Markdown 产物只在远端 Actions 实际运行后才构成远端证据。

### 题目变更影响分析

记录内容变更时，可把稳定题目 ID 传给只读影响分析命令：

```sh
npm run challenge:impact -- --question-id <题目ID> [--question-id <题目ID> ...]
```

命令按当前清单中题目所属挑战组和题目难度，列出该组所有同难度任务。组卷从同难度候选池中选题，因此这些任务都可能抽到变更题；结果包含已发布、计划中和已暂停组。报告只列 ID、难度和任务范围，不读取或输出题干、答案、讲解或学生数据，也不会修改清单或本地存储。

退出码 `0` 仅表示所有输入 ID 都能映射到当前任务范围，不表示质量门禁或内容审校通过；退出码 `1` 表示至少一个 ID 不在当前清单、未被挑战组引用或无法映射，必须运行完整 `npm run challenge:quality` 并按风险等级扩大回归；退出码 `2` 表示参数或加载失败。命令只读取当前清单；如果变更修改了题目难度、组引用关系或删除题目，当前映射不包含完整的变更前范围，必须对照变更基线并运行完整质量门禁。

内容变更同时更新[内容变更记录](CONTENT_CHANGELOG.md)；发布时更新仓库根目录 `CHANGELOG.zh-CN.md`。答案或评分修订只有在存在可靠的历史证据时才可补偿；本地不保存完整作答历史，因此无法证明时保留既有奖励。

- [ ] 内容变化已更新[内容变更记录](CONTENT_CHANGELOG.md)；发布摘要已更新根目录 `CHANGELOG.zh-CN.md` 或说明“不影响用户可见行为”
- [ ] 先观察到新增测试按预期失败，再实现功能
- [ ] 单元、集成和端到端测试覆盖与改动相称
- [ ] 检查现有学习功能回归
- [ ] 核对题目内容、测试覆盖率和 `npm run challenge:quality` 可发布状态报告；需要时另做人工教学审校
- [ ] 说明数据库迁移及回滚风险
- [ ] 高风险内容变化已运行全量质量门禁并完成必要的人工教学检查；不得声称 CI 已代替人工检查
- [ ] 未引入未经批准的服务端依赖或个人信息收集
