# 闯关系统开发协作指南

本文是闯关子系统的协作指南，不会覆盖仓库根目录 `AGENTS.md`。仓库规则和用户当前明确要求优先；本文只补充闯关功能的约束。

## 目标

在不改变现有学习任务语义、不删除学习进度的前提下，实现独立的闯关子系统。

## 开发规则

1. 修改闯关功能前，阅读仓库 [`README.md`](../../README.md)、本文档、[方案入口](README.md)、[产品需求文档](PRD.md)、[决策冲突与待验证事项](DECISION_CONFLICTS.md)、[仓库基线](REPOSITORY_BASELINE.md)及[需求追踪矩阵](REQUIREMENTS_TRACEABILITY.md)。
2. 先检查当前仓库，不要臆测路径、数据形状、拉取请求合并状态或依赖情况。
3. 遵循 TDD：先写失败测试，再实现最小行为，最后整理代码；每项行为变更都要有适当的测试。
4. 保持本地优先和静态部署；未经明确批准，不添加后端服务。
5. 组卷和测试使用确定性种子。不得绕过知识覆盖检查或发布质量门禁。
6. 数据库升级时保留未完成的闯关快照与已有数据；迁移失败不得覆盖原数据或学习进度。
7. 不得弱化 Q78～Q84 已确认决定：不得重新要求独立审核、因内容编辑自动撤销审核、增加紧急远程控制服务或应用内通知。
8. 避免收集学生敏感信息。诊断导出必须遵循字段白名单。
9. 任何影响行为的修改都要更新需求追踪矩阵和发布记录。
10. 不得只凭方案文档声称功能完成；必须通过测试并核对验收条件。

## 内容变更风险分级

REQ-077 已确认采用三级风险。以下等级示例和检查范围是工程实施约定，用于落实该决定；它们不是新的产品规则或额外批准门槛。每个包含题库变化的拉取请求须标注风险等级和理由。风险分级用于选择检查范围，不改变审核状态，也不要求作者之外的独立审核人。

| 等级 | 典型变化 | 必要检查 |
|---|---|---|
| 低 | 不改变答案、知识范围和挑战引用的文字修正；仅影响一个题目或单元的非评分文案 | 核对改动上下文、中文表达和年龄适配；运行题库清单校验及相关测试 |
| 中 | 修改题意、提示、讲解、难度标签、知识点标签或候选池；影响范围能从清单确定 | 低风险检查；检查每个引用该题的挑战任务、答案和覆盖关系；记录风险理由和实际检查结果 |
| 高 | 修改答案键/判题语义、稳定 ID、生命周期、共享题型控件、评分逻辑或数据结构；影响多个学科/年级；或处理已确认的严重错误 | 明确完整影响范围，执行全量内容与自动回归门禁，并进行必要的人工教学检查；严重问题按 REQ-082 手动禁用后走常规静态发布 |

若无法确认引用范围或风险等级，按高风险处理。作者可自审；高风险仍须完成必要人工检查，但不得借此要求独立审核者、额外审核证明字段或在编辑时自动撤销 `approved`。当前 CI 会对拉取请求执行全量单测、覆盖率、静态构建和浏览器测试；这些自动检查不替代人工教学检查。拉取请求可简述检查范围，但不要求另附审核证明。

内容变更同时更新[内容变更记录](CONTENT_CHANGELOG.md)；发布时更新仓库根目录 `CHANGELOG.zh-CN.md`。答案或评分修订只有在存在可靠的历史证据时才可补偿；本地不保存完整作答历史，因此无法证明时保留既有奖励。

## 拉取请求检查清单

- [ ] 标注关联的 REQ 和验收条件
- [ ] 内容变更已标注风险等级、理由和影响任务；不涉及题库时注明“不适用”
- [ ] 内容变化已更新[内容变更记录](CONTENT_CHANGELOG.md)；发布摘要已更新根目录 `CHANGELOG.zh-CN.md` 或说明“不影响用户可见行为”
- [ ] 先观察到新增测试按预期失败，再实现功能
- [ ] 单元、集成和端到端测试覆盖与改动相称
- [ ] 检查现有学习功能回归
- [ ] 核对题目内容、覆盖率和可发布状态报告
- [ ] 说明数据库迁移及回滚风险
- [ ] 高风险内容变化已运行全量质量门禁并完成必要的人工教学检查；不得声称 CI 已代替人工检查
- [ ] 未引入未经批准的服务端依赖或个人信息收集
