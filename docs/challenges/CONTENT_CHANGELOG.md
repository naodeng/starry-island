# 闯关内容变更记录

本文规定题库变更与 GitHub 发布摘要的记录格式。实际发布摘要统一维护在仓库根目录 `CHANGELOG.zh-CN.md`；本文不代替题目审核清单，也不扩大 REQ-079 对审核元数据的最小字段要求。REQ-077 已确认需要三级风险；具体分级示例和记录字段是工程实施建议，不增加新的产品规则。

## 何时记录

题目、答案、讲解、知识点映射、生命周期或挑战引用关系发生变化时，在同一拉取请求中补一条记录。只改文档、样式或不影响题库的代码时，不需要伪造题目变更条目，但仍按版本更新摘要的约定填写发布说明。

## 记录字段

- 日期、相关 REQ 与变更摘要。
- 变更的稳定题目 ID、来源单元，以及引用这些题目的组和任务；影响范围暂时无法确定时，写明已扩大到全量题库/回归检查。
- 低、中或高风险等级及判定理由。
- 适用的静态校验、受影响任务测试和人工教学检查范围；记录检查结论即可，不要求额外审核证明或独立审核人。
- 若改变答案或评分，说明是否存在可靠的历史作答证据。没有证据时保留既有奖励，不推测性重评分或撤销。
- 对应 `CHANGELOG.zh-CN.md` 的面向用户摘要，或说明该变更不影响用户可见行为。

可使用 `npm run challenge:impact -- --question-id <题目ID>` 生成受影响任务列表，再把结果记入本条记录。命令返回 `1` 或提示范围未知时，必须按完整题库质量门禁处理；映射成功也不代表内容审核或回归已完成。命令只依据当前清单；难度、组引用关系或题目是否存在发生变化时，应对照变更前基线恢复旧范围。

## 可复制的记录模板

```markdown
### YYYY-MM-DD｜简短变更主题

- 相关需求：REQ-...
- 变更摘要：
- 题目 ID / 来源单元：
- 受影响挑战组与任务：
- 风险等级与理由：低 / 中 / 高；……
- 自动检查：命令与结果
- 人工检查：按风险等级完成必要检查；允许作者自审，不要求额外证明材料
- 历史奖励：无评分影响 / 有可靠证据并按证据补偿 / 证据不足，保留原奖励
- 发布摘要：对应 `CHANGELOG.zh-CN.md` 条目或“不影响用户可见行为”
```

记录中的风险等级和验证摘要用于变更影响追踪；它们不是新的题目审核元数据。题目审核记录仍遵循当前声明式清单允许的最小字段。内容指纹变化仍可追踪，但不得自动撤销 `approved`；编辑本身也不额外触发发布暂停。
